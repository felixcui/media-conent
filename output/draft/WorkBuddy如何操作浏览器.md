# WorkBuddy 怎么操作浏览器？两条路径，一篇讲清

> 让 AI 替你"上网干活"，其实比想象中简单。

以前让 Agent 帮忙干活，最怕遇到没有 API 的网站——登录后台、查数据、填表单、点按钮，样样都得自己动手。现在，WorkBuddy 已经能像人一样打开浏览器、点击、输入、读取信息，甚至把多个网站上的工作串起来。

这篇文章就把 WorkBuddy 操作浏览器的两条主流路径、底层原理和真实案例，一次性讲清楚。


## 一、WorkBuddy 自带的「浏览器操控」能力

这是 WorkBuddy 内置的能力，无需额外找工具，配置入口在：

**设置 → 智能体 → 让 WorkBuddy 控制浏览器**

这里会显示「已安装 +版本号」，下方提供 **Chrome、Edge、QQ 浏览器**三个扩展程序的安装入口。安装并连接后，即可让 WorkBuddy 控制你的浏览器。

**怎么用？**

直接新建任务，用自然语言下达指令即可。例如：

> 用我电脑里的 QQ 浏览器打开 bilibili.com，搜索"roadster 发布会"，按最多播放排序找到近期热门视频……

收到任务后，WorkBuddy 会先确认浏览器扩展已连接，再打开目标网站。执行记录中会显示当前进展，浏览器里也能看到它正在访问的页面。

**几个关键特性：**

- **沿用已有登录态**：安装配套扩展、开启浏览器连接并授权后，任务会复用浏览器里已有的登录状态，可直接进入需登录的页面。
- **不抢占你的操作**：网页操作集中在独立的 WorkBuddy 标签页组中，不抢占用户的鼠标和当前窗口，用户可以同时处理其他工作。
- **敏感环节需人工确认**：涉及支付、注册提交或验证码等环节，按产品设定仍需人工确认。

需要注意的是，这项浏览器操控能力目前仍处于 **Beta 公测阶段**。



## 二、安装 BrowserSkill（腾讯开源的浏览器自动化工具）

BrowserSkill 是腾讯开源的智能浏览器自动化工具，让 WorkBuddy 能够像人一样操作网页，自动填表、点击、翻页、截图，完成任何需要浏览器的复杂任务。

**安装步骤：**

1. **安装技能**：在 WorkBuddy 工作台选择技能，搜索 BrowserSkill，点击安装；也可以在对话框直接发一句"安装这个 https://github.com/Tencent/BrowserSkill"。在"专家·技能·连接器"里搜索并添加即可。
2. **安装 bsk CLI**：WorkBuddy 会自动安装 bsk CLI（如 v0.1.11，装在 `~/.local/bin/bsk`）。
3. **手动安装浏览器扩展**（AI 装不了，必须手动）：用 Chrome 或 Edge 打开对应商店点"添加至浏览器"。
   - Chrome：`chromewebstore.google.com/detail/hhcmgoofomhgciiibhipgmgkgnoenaoi`
   - Edge：`microsoftedge.microsoft.com/addons/detail/browserkill/emacgiaaaiojkkpkddmmdfhmokgmnikg`
4. **确认连接**：点开扩展图标，启用本地连接，等状态变绿/弹窗显示"connected"（已连接），再回复 WorkBuddy 一声即可继续。
5. 随后根据提示重启 WorkBuddy 就能用了。

**使用方式：**

新建任务后输入 `/` 调用 BrowserSkill，再输入指令，例如：

> 帮我打开京东，定位到我的订单页面。

它同样能沿用已有登录状态，读取页面、点击、填表和提取数据。

**与自带能力的区别：**

WorkBuddy 自带浏览器操控在独立标签页组中执行任务；BrowserSkill 则提供独立的 Agent 窗口，以及操作录制与回放等进阶功能。作为开源工具，它也能供其他 Agent 调用并支持进一步定制。


## 三、底层原理：Agent 到底怎么"看懂"网页？

Agent 控制浏览器，本质上是在模仿人的行为——看一眼页面，点击一下，然后继续观察。整个过程可以拆成一个循环：

**接收任务 → 读取页面 → 判断下一步 → 执行动作 → 检查结果 → 继续或结束**

其中所有决策，都是由大模型来控制的。要理解它，可以拆成三个问题：

**① 怎么执行操作？**

控制浏览器执行操作，主要有三种路径：

- **浏览器调试协议（CDP）**：浏览器开一个调试端口，外部程序连上就能指挥浏览器干活。Playwright、Puppeteer 走的都是这条路。能力最全，但网站容易察觉你在用程序控制，容易被拦截。
- **浏览器内扩展程序**：控制代码作为扩展跑在浏览器内部，直接操作页面，再通过本地服务把能力开放给 Agent。最大优势是登录状态和你本人操作时一模一样。BrowserSkill 走的就是这条路。
- **操作系统层**：在桌面上模拟鼠标键盘，或截屏给模型看。网站察觉不到痕迹，但每走一步都要截屏加识别，速度慢得多，窗口大小、缩放比例一变，点击位置就失效。

**② BrowserSkill 的调用流程是怎样的？**

- **Agent 发起任务**：通过 bsk CLI 下发浏览器操作指令，CLI 将指令交由本机 daemon 处理
- **Daemon 本地转发**：Daemon 将请求安全地传递给浏览器扩展
- **Agent Window 隔离执行**：扩展在独立的 Agent Window 中完成自动化操作，不触碰用户日常窗口；必要时向用户发起借用（Borrow）请求，使用已有的标签页

理解了这套原理，就很容易明白为什么装 BrowserSkill 时，既要装 bsk CLI，又要装浏览器扩展。

**③ 怎么理解页面？**

拿到页面信息有三种方式：

- **DOM 树**：整个页面结构、内容的表达，信息最全面，但包含大量嵌套标签和样式，容易把上下文占满。
- **无障碍树**：重点描述元素的角色、名称、能不能操作和具体的值，信息更精简，但很依赖页面是否写得规范。
- **页面截图**：直接让大模型看页面长什么样，视觉直观，但识别准不准取决于视觉模型的能力。

实际实现时，这几种方式通常会配合使用，一起帮助 Agent 判断下一步该做什么。


## 四、真实案例：它到底能干成什么事？

**案例一：B 站评论舆情简报**

在一项围绕特斯拉 Roadster 发布会相关视频的评论整理任务中，用户把这串步骤交给了 WorkBuddy：去 B 站检索视频、收集高赞评论、归纳观众反馈，最后交付简报和评论明细。

任务沿用了 QQ 浏览器里已有的登录状态。WorkBuddy 打开 B 站，按播放量排序筛选视频，进入评论区核对内容，再结合脚本完成采集和整理，最终汇总了 **3 个视频下的 600 条高赞评论**，所收集的评论累计获得约 **13.9 万次点赞**。最终生成一份 Markdown 舆情简报和一份 CSV 评论明细。

**案例二：招聘岗位分析**

借助 WorkBuddy + BrowserSkill，自动去招聘网站获取岗位数据。提示词如下：

> /BrowserSkill 打开我已经登录的 BOSS 直聘，搜索"AI Agent 开发工程师"相关岗位，帮我收集成都最近发布的 30 个有效岗位……整理成 Excel。最后分析一下，现在企业招聘 AI Agent 工程师最看重哪些能力。

任务发出后，它立马打开了招聘网站，登录态复用了之前的，并在搜索框中输入关键词开始搜索。

**案例三：按验收标准自动测试**

开发一个登录功能时，可以这样描述：

> 帮我完成用户登录功能，并按照以下标准进行验收…… 功能开发完成后，使用 BrowserSkill 在浏览器中逐项测试。记录每一项的测试结果；如果发现问题，继续修改代码并重新测试。只有全部验收标准通过后，才能结束任务。

这样，Agent 会形成一个完整的工作闭环：

**编写代码 → 启动项目 → 操作浏览器测试 → 对照验收标准检查 → 修复问题 → 重新测试**

交付质量因此更高。



## 五、写在最后

让 AI 直接去浏览器帮你干活，而且还不抢你鼠标——这大概就是浏览器自动化对 WorkBuddy 最大的意义。

以前遇到没有 API 的网站，很多事情就卡住了。现在 AI 可以像人一样进入网站、点击、输入、读取信息，甚至把多个网站上的工作串起来。这意味着，很多原本需要人工配合的任务，现在有机会让 WorkBuddy 独立完成。

当然，验证码、复杂登录这些问题还没完全解决，但方向已经很明确了。

如果你也经常用 WorkBuddy，建议装上试试，很舒服。
