[**AI 写代码越来越快，谁来守住章法？**](https://mp.weixin.qq.com/s/jwPPuBWg6J9mu89rBXAXrQ)

[**构建 AI 时代的知识底座：直播数据 LLM Wiki 实践**](https://mp.weixin.qq.com/s/1J3EEmjmisxUejV7fpZF5g)
大淘宝直播数据团队的实践。领域知识散落在代码注释、配置、钉钉文档和沟通记录里，后果是口径矛盾、人走知识就断、文档三个月后和线上对不上；直接套 RAG 只能把找不到变成找到了但答不准，因为它不改变原材料本身的状态。LLM Wiki 的做法是在检索前加一道编译，把 DDL、代码等源材料预先加工成结构化、可验证的知识资产。三条支柱：Schema 即契约，每页是 frontmatter 加正文，生成器、图构建器、健康检查、检索共用同一套结构；显式关系图，表的上游下游、指标由什么算出都写在字段里，脚本直接取，不用解析自然语言；分层目录 ready/pending/archive，只有 ready 参与生成，把材料是否可用变成目录上的物理事实。再配 Agent 编排做自动构建与检索。效果：血缘查询提速 15 倍，遗漏率降到 0%，指标召回、SQL 生成、模型迭代都明显提效。

Anthropic《Building always-on agents》的中译。核心框架先说清一个误解：**持续在线的 agent 不是一直跑着的进程**，而是**大部分时间休眠、被事件叫醒后跑一次**——这段叫一次 **run**，休眠期间**不消耗 token**。一次 run 分四步：**事件到达 → 会话启动 → 执行 Agent 循环 → 状态写回存储**，供下次沿用。能力来自**外围的五个部件**：①**事件收件箱**（所有事件源先投递，再由工作进程领取，避免并发乱套）；②**定时器**（给自己定的跟进、给你的周期任务，到点只加事件）；③**记忆**（跨 run 保留，只存别处查不到的）；④**权限**（风险最大：凭据隔离、危险动作分类器拦截、需批准的先挂起）；⑤**发件箱**（发消息／不发／反问，默认安静）。门槛下降的两个前提：**模型判断更准**（知道何时该主动找你）、**推理成本下降**（长程任务受益）。

[**Anthropic刚教的24小时agent，我当天做出来了**](https://mp.weixin.qq.com/s/MtPgNFKT2Ceb6g20WxK6zw)
作者读完 DeepSeek Harness 的《Super-agent 设计探索》（10/31）和 Anthropic 的《Building always-on agents》（11/13），**当天就照着做了一版**，随开源 Coding Agent 驾驶舱 **FanBox 2.20.0** 发布。DSH 要的四件事：**连续**（感觉始终只有一个 agent）、**高效**（不等上一件干完就接下一件）、**主动**（没人 @ 也能发现该干的活，不该介入时保持安静）、**持久**（一直在线、异常自恢复）。Anthropic 的落地拆成**五个部件**：①**事件收件箱**（消息/webhook/定时任务先落库，**单工作进程**取、连发三条并成一轮只回一次）；②**定时器**（agent 给自己定的跟进 + 你的周期任务，到点只往收件箱加事件）；③**记忆**（只存别处查不到的，其余存指针，并记住「已经告诉过你什么」）；④**权限**（原文称风险最大：凭据放在 agent 够不着的代理里、分类器拦危险动作、需批准的工具调用先挂起）；⑤**发件箱**（三种结尾：发消息／不发／挂起问你，主张**从安静开始赢得注意力**）。DSH 的初步实验：约 **300 条消息**（其中约 **20 条**真要干活），Super-agent 中位 **12.4 分钟**出结果，**95% 在 15.7 分钟内**完成。

[**DeepSeek Harness成了第一个让我上瘾的Agent**](https://mp.weixin.qq.com/s/zFgb_EUXWimu-mjwvBeCqg)
DSH 和任务型 Agent 的差别在于它是**一张敞开的工作台**：不是帮你把一件事做完，而是**可塑性高到让你随手就想动手改**。作者给了三种玩法：**从零手搓插件**（如 AI 阅读助手）、**基于现有插件二次改造**、**把任意 GitHub 项目一键转成 DSH 插件**；插件之间可以联动，最后沉淀成**个人工具箱**，每折腾一次都是在积累而不是一次性消耗。生态数据（官方披露）：第三方插件已破 **3.5 万个**，约 **60% 的活跃用户**做过或装过至少一款第三方插件。
