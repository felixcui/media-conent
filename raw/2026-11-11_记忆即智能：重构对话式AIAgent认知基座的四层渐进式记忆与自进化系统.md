## 摘要

对话式 AI 的共同病：没有记忆，换个渠道、隔个会话就重新认识你。文章用一套**四层渐进式记忆**从原始对话流逐层提炼成认知：**L0 数据底座**（只记录不加工）、**L1 感知层**（只观察不决策，抽每条消息的意图、情绪、回溯信号、行为完成度）、**L2 决策层**（唯一调度者，拿阶段状态机 + 策略库 + 规则库决定“该走哪条路”）、**L3 画像层**（长期记忆，用户维度六个特征：价格敏感度、信任度、操作熟练度、偏好时段、忙碌标签、回复风格）。节奏也是分层的：L0 实时落库 → L1 每条消息毫秒级 → L2 每条消息实时调度 → L3 24 小时定时 + 实时微调。关键设计原则是**每层只做一件事、决策权只给一层**，配合画像演化与策略效果闭环，做到“越用越懂你”。

## 背景

本文将结合货拉拉实际经验，系统介绍在对话式AI Agent场景基于 **四层渐进式记忆架构** ，实现从 **"传状态"到"认知自进化"** 的范式跃迁：

- **分层记忆** ：以 **数据底座→感知层→决策层→** **画像** **层** 的渐进式加工链路，将原始对话流逐层提炼为可被模型直接消费的结构化认知，完成从"原料"到"养分"的转化；
- **认知飞轮** ：画像维度千人千面实时演化，沟通策略基于效果闭环自动汰劣留优， **系统越用越懂用户、越用越精准** ，构建数据驱动的自增长智能闭环。

## 01 为什么要做记忆系统

## 1.1 背景

货拉拉用户普遍活跃于多个触点（App、小程序、H5、电话、即时通讯等），是天然的高价值用户池。用户的绝大多数行为都围绕「下单」展开，并在核心的下单动作之外，延伸出领券、邀请好友、复购等一系列伴生行为。

用户的转化通常是跨天甚至跨周的长链路（咨询/引导 → 领券/比价 → 下单/激活 → 复购/邀请）。用户从被触达到最终完成转化，中间可能经历 3–5 次会话中断、跨电话/即时通讯多个渠道。链路越长、断点越多，对对话系统的要求就越高：它必须记得住用户处于哪个阶段、上一次聊到哪、为什么犹豫或拒绝过；看得懂用户当下的真实意图与情绪；说得对因人而异的沟通策略——而这一切的前提，就是记忆。没有记忆，后面的"懂"和"对"都无从谈起。

## 1.2 章鱼的悲剧

章鱼是天才，但每一只都是孤立的、独立的天才。它们能：开瓶盖、伪装成 15 种生物、识别人脸、记住照护者，有实验显示会"做梦"。

但章鱼有一个绕不开的短板——它们没法把"智慧"传下去：会捕猎的章鱼妈妈，不会教小章鱼捕猎；会用椰子壳当铠甲的章鱼，不会把这招传下去。所有的"经验"——每一只都要用一辈子重新攒出来。

这正是常见对话系统正在重演的悲剧：

- 每一次对话沟通，都像一只"孤立的章鱼"——本轮聊得再顺，下一轮一切清零；
- 用户昨天拒绝过"费用贵"，今天换个渠道进来，系统又从头推荐；
- A 用户被"收益案例"打动、B 用户对"便宜"免疫——这些经验散落在成千上万通会话里，没人汇总、没人继承。

没有记忆的AI，就像没有代际传承的章鱼：个体再聪明，族群永远从零开始。

## 1.3 一个真实的"事故"复盘

我们抽了50通即时通讯渠道被用户删除的对话做复盘，发现被用户删除的原因不在策略、提示词、知识库这些表层，而在更底层：AI 没有记忆，就做不了跨渠道、跨会话的判断。它记不住用户上一句、上一次拒绝的原因，只能机械地"看到 A 状态 → 跳 B 策略"，最终把用户推远。

## 02 怎么做记忆系统

## 2.1 金牌顾问是怎么记住一个用户的？

一次做前期调研时，一位金牌顾问说了一句话：

> “我不需要客户说'我拒绝了三次'，听语气、看回复间隔、推脱理由，我就知道他是真忙还是嫌贵、是真不需要还是再推一下就成。”

原来金牌顾问从来不是靠"标签"做决策，而是靠多模态、多层次、跨时间的记忆推理来理解用户。仔细拆解他这句话，背后藏着完整的 4 层认知链路：

| **阶段** | **关注内容** |
| --- | --- |
| 听原始语气 | 声音信号、未加工的事实 |
| 当时观察 | 单条消息的意图/情绪判断 |
| 当下判断 | 综合上下文给出当前该推还是缓 |
| 长期认知 | 用户是什么人、有什么偏好 |

这给了我们两个关键启发：

a. 记忆是连续的：我们要记录的不是"用户拒绝了"这个结果，而是"从敷衍到松动"的完整变化过程；

b. 记忆是分层的：信息有轻重之分，应按"原始数据 / 当时观察 / 当下判断 / 长期画像"四层递进存储。

## 2.2 业内常见做法

### 2.2.1 常见记忆系统

绝大多数对话系统采用 "传状态" 模式：把对话中的关键事件抽象为扁平标签（如"用户状态=未下单"、"拒绝原因=在忙"、"意向=高"），作为 Prompt 变量注入 LLM。这种做法能跑通，但对于复杂任务会有致命问题：

| 问题维度 | 具体表现 |
| --- | --- |
| 数据扁平 | 仅存结论标签，不存过程信息（语气、推脱频次），模型看到的是孤立标签而非完整证据链。 |
| 情绪无法回溯 | 只看当前消息字面，无法结合历史纠偏（如"好的好的"实为敷衍），误判后强行推进易导致用户流失。 |
| 跨会话无法续接 | 仅记录"上次拒绝"，不记中断阶段与上下文，恢复等同于从头开始。 |
| 跨渠道无法打通 | 电话与即时通讯各存一份记忆，同一用户在两个渠道被当成两个新人对待。 |
| 个性化粒度粗 | 不区分"真忙 vs 推脱"、"价格敏感 vs 嫌麻烦"，千人一面。 |
| 无自进化能力 | 策略效果黑盒，优化全靠人工复盘迭代，迭代周期 2–3 周。 |
| Token 效率低 | 无关字段全量注入 Prompt，关键信息反而缺失；且每次都要重发全部历史。 |

2.2.2 什么是好的记忆系统

好的记忆系统不是把所有信息都塞进上下文，而是只保留最相关的信息，其他内容按需存取，让模型更专注、更高效、更聪明。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/T6owctB6ycZXZ38W8EdoKyo0W5ibhrXXUsr43icdLKINhrRicLETbQIMfIDFkRTw5tW56V7quiabnjDTyYTpkMfTpiaINKAmgbqycyynYuJ7DGfc/640?wx_fmt=png&from=appmsg)对于某一类具体业务场景，也是一只"新生的章鱼"，用户每开一个新对话，对 AI 来说，就是一次"投胎"：如果不记得上周用户说过什么、不知道用户上次为什么拒绝、不知道用户的偏好&情绪&节奏，一切从零开始。这次我们要做的，就是给这套系统装上"打破章鱼悲剧"的能力——让它能记住、能累积、能进化。

鉴于此，我们结合调研内容重新设计了 4 层渐进式记忆架构——核心思想是：

```
把"扁平标签"升级为"原始数据→当时观察→当下判断→长期画像"的递进加工链路，让每一层都建立在上层之上
```

## 2.3 四层架构总览

| **层级** | **名称** | **职责** |
| --- | --- | --- |
| L0 | 数据底座 | 只存不判：原始消息、对话原文、事件流（100% 还原现场）。 |
| L1 | 感知层 | 只观察不决策：每条消息的意图、情绪、回溯信号、行为完成度。 |
| L2 | 决策层 | 唯一调度者：阶段状态机、策略库、规则库，"该走哪条路"由它说了算。 |
| L3 | 画像层 | 长期记忆：用户维度的 6 个核心特征（价格敏感度、信任度、操作熟练度、偏好时段、忙碌标签、回复风格）。 |

渐进式体现在两个层面：

```
L0 实时落库 → L1 准实时分析（每条消息后毫秒级）→ L2 实时调度（每条消息后）→ L3 24h 定时 + 实时微调
```
```
从"原始数据"到"当时观察(意图理解)"到"当下判断"到"长期认知"，每层都建立在上层之上
```

## 2.4 各记忆层定义

### 2.4.1 L0数据底座 — 只记录不加工

L0 是整个记忆系统的事实层，只负责忠实记录对话与事件的原始信息，不做任何加工或判断：

- 原始消息：用户/AI 的每一条消息原文、时间戳、消息 ID
- 对话原文：完整的对话流，可用于回溯

## 2.5 跨渠道记打通

用户在App、小程序、H5、电话、即时通讯等渠道是同一个用户，但在实现里容易被当成多个独立对话，记忆完全隔离。我们做了横向打通：

a. **身份层打通：** 以用户身份标识为主键，关联电话、即时通讯的所有会话。

b. **画像层打通：** L3 画像是渠道无关的——价格敏感度、信任度等维度在两个渠道共用，凌晨重算时合并两个渠道的数据。

c. **阶段层桥接：** 电话结束时的 用户状态 写入 L0表，即时通讯开场时读取上次的 用户状态，决定从哪个引导目标（下单/领取/激活/分享）切入。

04 总结

1. 认知的转化：技术永远在演进，我们这次最大的收获不只是关键指标的提升，更是认知上的转变。每只章鱼都是天才，但每只都要从零开始攒经验——这是它们在演化上不得不付的代价。但对 AI 来说，我们不必走这条路。AI 可以站在前代积累的肩膀上，一代比一代更懂人。
2. 记忆的建立：从"传标签"到"建记忆"——AI 的下一个突破不在更准的识别，而在更深的理解。从 L1 单条意图识别升级到 L0-L3 跨时序推理，把"上下文"和"时间"还给 AI，它就能从机械执行变成有温度的沟通者，并让策略随效果自动汰劣留优。
3. 能力的升维：记忆系统的应用从来不是单一场景化建设。这套"分层记忆 +认知飞轮"的底座，在用户全生命周期（从获客、激活到促活、流失挽回），在电话、即时通讯乃至任何需要"长期懂人、持续对话"的 Agent 场景，都能得到进化沿用——让 AI从单场景工具，长成越用越懂人的认知基础设施。
