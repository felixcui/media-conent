# Scale AI创始人：AI是文明史上千载难逢的机会丨Y Combinator

**作者**: Capihom

**来源**: https://mp.weixin.qq.com/s/clJJ2Pm0gGe8KFJn0zMlqg

## 摘要

Scale AI创始人Alexandr Wang指出，AI正带来文明级的创业机会。他建议年轻人先进入真实商业环境快速吸收知识，创业需找准时机，Scale正源于他训练模型时发现的数据缺口。面对早期投资人的质疑，他强调要基于亲身实践坚持非共识判断并快速修正。他认为当前AI的瓶颈在于技术扩散，Agent的普及让小团队具备大组织的执行力，未来智能将充裕，稀缺的将是愿景与野心。

Alexandr Wang 给18岁的自己提出的建议是：培养自己对未来走向的内在指引，并坚定信念，不受外界干扰。在2026年创业学校（Startup School 2026）上，Scale AI（YC S16）的创始人——现任Meta超级智能实验室负责人——与Garry Tan探讨了如何从零开始重建前沿实验室、人才密度为何会成倍增长，以及如何发现值得你二十多岁时全力投入的指数级增长机会。

## 十七到十九岁，先去公司里看清现实

Wang 在新墨西哥州洛斯阿拉莫斯长大，长期参加数学和计算机竞赛，也很早就想做一件足够大的事，只是当时说不清具体路径。高中毕业后，他受一位热衷编程、去过 Palantir 实习的朋友影响，先到硅谷的 Quora 工作，随后进入 MIT，并在 19 岁创办 Scale。

"从公司外面看，你根本不知道公司怎样运转，也不知道人们如何做产品、迭代和共同决策。"

他后来把工作和学校看成两种训练，Quora 让他第一次看到多人协作的真实现场。MIT 给了他探索兴趣的空间，他在那里训练模型，也赶上 TensorFlow 刚发布的阶段。 **十七到十九岁之间，他的方向一直在变，稳定下来的能力只有一项：靠近做事的人，然后快速吸收。**

那两年里，他形容自己像一直在“对着消防水管喝水”，每天都被身边的人和新知识改变。YC 后来延续了这种训练，一边支持创始人，一边在想法站不住时把话说得很重。Wang 认为年轻时最需要的环境，正是允许方向改变，却不允许停止学习。

## 好点子也会死在错误的时间里

Wang 申请 YC 时的项目方向，是一名帮助患者获得医疗服务的 AI Agent，当时还未出现 Scale 这个名字。这个方向今天已经出现很多真实产品，2016 年却太早。团队做了一两个月后，YC 合伙人 Jared Friedman 把他们叫到一边，直说自己看不出项目能走到哪里。

"这是一个最终会存在的产品，可当时的时机错了。"

这句直话迫使团队回到起点，Wang 随后想起自己在 MIT 训练模型时反复碰到的问题。训练需要三样东西：云端算力账户、能够运行的代码和数据集，前两样在线点几下就能取得，数据却缺少有效的供应方式。 **Scale 的起点来自这个亲身遇到的缺口，热门榜单在这里没起作用。**

当时大型语言模型还未进入主流，自驾车和计算机视觉先成为 Scale 的市场。今天回看，那些早期模型像玩具，可训练流程里对高质量数据的需求已经非常清楚。Wang 先解决自己熟悉的问题，再跟着客户把一项基础能力做成公司。

## 没人认同的判断，才需要自己的罗盘

Scale 早期服务自动驾驶和计算机视觉公司，数据在当时仍是一门乏味生意。公司收入和增长表现不错，投资人见面时依旧反复追问这项业务能否长久。多年后，同一批曾经拒绝投资的人开始写文章，把数据称作 AI 最大的商业机会之一。

"你要相信一组别人都不认同的判断，也要比所有人更早看见它。"

Wang 认为，成功公司往往在共识形成前默默做了很多年。创始人很难靠周围人的评论决定方向，因为人群本身会不断改变口径。他也不神化创业天赋，任何人第一次创业时都不擅长这件事。 **早期竞争比的，是谁能更快承认自己做得很差，再持续修正自己。**

早期投资人看不懂 Scale，还有一个朴素原因：他们大多从未亲手训练模型，自然感受不到数据缺口有多麻烦。Wang 每天都在问题里面工作，由此形成了比市场报告更牢固的判断。创始人的信念如果只来自外部叙事，市场口风一变就会跟着摇摆。

## Agent 让创业公司变成“机甲巨人”

Wang 判断，当下的瓶颈已经从模型进步转向技术扩散。即使模型从今天开始停止提升，现有能力也足以让经济和组织经历几十年变化。大量企业尚未把模型接入日常工作，这段落差正给新公司留下位置。

"这可能是一次文明级的机会，让有梦想、有愿景和野心的人去塑造未来。"

十年前，创业通常像大卫挑战歌利亚，小团队必须寻找狭窄切口，绕开大公司的资源优势。Agent 改变了这场对抗，充分使用 Agent 的创业公司像一名被机械增强的歌利亚，能用很小团队承担过去需要大组织完成的工作。 **资源差距仍然存在，单位人数能够调动的执行力却已经变了。**

这种优势不会自动出现，创业公司需要把 Agent 放进最有价值的工作，并围绕它重新安排流程。大企业拥有更多员工和预算，也背着旧系统、审批和既有分工。小团队如果从第一天就按 Agent 的能力设计公司，速度可能超过传统巨头。

## Meta 重建实验室，第一步是提高人才密度

Wang 加入 Meta 后，判断 Llama 4 的原有轨迹无法满足公司的需要，于是从零开始重新设计前沿实验室。团队九个月后推出 Spark 1，又在两个月后发布新图像模型和 Spark 1.1。与传统互联网产品相比，前沿模型更接近科学研究，组织要容纳大量实验、算力扩张和失败。

"人才密度会自然复利，优秀的人越多，越能吸引最优秀的人加入。"

Meta 同时准备更大的模型、面向开发者的 Agent harness 和开源模型。主持人称 Spark 1.1 在 Agent 工作流里接近 Opus，价格约低八倍，Wang 在结尾再次提到这一差距。 **他的目标是让模型能力不被少数富裕公司配给，让更多开发者有条件试出下一波产品。**

Wang 把前沿实验室看成一种会生长的组织，需要同时跟上模型能力、算力供给和使用量的指数增长。为开发者准备的 harness 则优先解决速度、可靠性和扩展性，让复杂的多 Agent 配置可以稳定运行。主持人把现有工具形容成会在路边抛锚的法拉利，Wang 希望新工具至少少抛几次锚。

Meta 对“个人超级智能”的设想覆盖数十亿人，每个人都拥有理解自身背景、帮助完成目标的系统。平台上目前约有两亿家企业，Wang 希望 AI 工具把这一数字推向数十亿，个人 Agent 与企业 Agent 直接协作。这里的超级智能更像扩展人的行动范围，不负责替所有人统一决定未来。

## 智能变得充裕以后，愿景开始稀缺

Wang 回看过去十年，最好的模型曾经只能识别 YouTube 视频里的猫，现在已经能处理代码、研究和复杂操作。他认为继续争论超级智能究竟两年还是五年到来，消耗了太多注意力。模型会继续变强，更多人也会拥有能够替自己行动的 Agent。

"回头看时，最明显的事会是智能变得充裕，执行力也变得充裕。"

过去，聚集一群聪明人并让他们朝同一目标行动，是组织进步的重要限制。AI 可能把执行成本降低十倍甚至一百倍，随之上升的是创始人对方向的责任。 **当聪明和执行都能购买，清楚描述五到十年后的世界，并愿意经历麻烦把它做出来，才构成新的稀缺。**

他把 AI 的商业浪潮分成几次放大：自驾车之后，聊天机器人扩大约十倍，编码 Agent 又可能比聊天机器人大十倍。下一种交互形态出现时，市场规模也可能继续放大同样数量级。与此同时，世界仍未准备好承受全部能力，创业者还要帮助企业和政府适应，并处理生物安全、网络安全等风险。

## 代码减少了，系统思维反而更重要

面对计算机专业报名下降，Wang 仍然强调严谨、系统的思考。创业初期，他先亲手写代码，随后学习组织人；今天的年轻人先编排单个 Agent，再编排由大量 Agent 组成的组织。抽象层不断上移，工作对象发生变化，设计流程和处理依赖关系的能力依旧存在。

"接下来要解决的，是怎样让一百万个 Agent 协作，再让一万亿个 Agent 协作。"

他不建议年轻人只练语言表达、放弃技术推理，因为 Agent 组织仍然需要结构、反馈和边界。与此同时，人也要形成关于世界如何发展的判断，技术能力负责把系统运转起来，历史和价值判断负责决定系统往哪里去。 **系统思维仍然有用，它只是从代码文件移动到了 Agent 军团。**

Wang 预计未来十年的人类变化可能超过过去一百年，因此只会调工具远远不够。工程师需要理解复杂系统，创始人也要能说清自己希望技术把社会带向哪里。技术训练和人文判断在这里并不冲突，它们分别处理“怎样运行”和“为什么这样运行”。

## 百人工程团队的工作，被写进一个反馈循环

Wang 认为，近期最具体的机会在 Agent 循环。公司本身就是一组反馈回路：找到客户，让客户更满意，收入增加后再雇人，继续寻找客户。每条边过去由人推动，现在可以让 Agent 持续运行，并投入过去一千倍甚至一百万倍的 token。

"只要 Agent 循环和评估指标设置正确，一群 Agent 可以轻松超过一百名工程师的团队。"

这个结果依赖清楚的指标和可持续反馈，具体实现反倒朴素：skills、Markdown 文件、cron job 和 \`/goal\`。主持人问这是否算魔法，Wang 的回答是深入以后总会发现一切很日常。 **Agent 的数量并不会自动带来产出，能被测量、能纠错的循环才会。**

以客户增长为例，Agent 可以持续寻找客户、观察满意度和收入变化，再根据指标调整下一轮动作。公司里还存在许多更小的反馈回路，过去由不同员工接力完成。把目标、数据和评估接好以后，token 消耗增加才会对应到业务结果，而非只留下更长的运行日志。

## 写在最后

Wang 给十八岁自己的建议很简单：形成一套对未来的内部罗盘，再寻找增长最快、持续最久的曲线。起点可以很无聊，Scale 当年面对的只是给模型找数据。今天动手时，先选一个你反复遇到的问题，给 Agent 设清楚指标，让结果替你检验判断。
