# 把公众号文章做成带 IP 角色的解说视频（3 套提示词 + IP 动作库）

**作者**: 莫影

**来源**: https://mp.weixin.qq.com/s/7bJmC2KyPQt7RzJp871RiA

---

## 摘要

作者分享了将公众号文章改造成带个人IP形象（莫影兔）的竖屏解说视频的完整方法，附三套提示词和IP动作库。流程共九步：锁定终稿、改旁白定分镜、试听声音、获取词级时间戳、按语义切场景、定视觉系统、渲染画面、自动加人工检查、先出低清全片再出正式版。其中最关键的是“声音先行”——音频时间戳决定全部画面节奏，颠倒顺序会导致灾难性返工。

## 正文

莫影 莫影

在小说阅读器读本章

去阅读

公众号文章发别的平台，比如某书，内容太长不适合，于是我想着用视频的方式来表达。

先看效果。

把一篇我已经发过的公众号文章 [我把图书带货视频流程做成了 Codex Skill，开源了](https://mp.weixin.qq.com/s?__biz=MzYzOTAzNjU4Ng==&mid=2247484445&idx=1&sn=cf4cfbb22ae4e7432d6661208360bd22&scene=21#wechat_redirect) ，做成 98秒竖屏解说，中英字幕，主持人是我自己的 IP 形象——莫影兔。

听起来像"把文章丢给 AI，它就吐出来了视频"。生成视频其实很简单，但是想要视频整体效果满意，需要做大量功课。

和AI来回讨论了不知道多少次已经数不清了。用Codex试错了10几个版本是有了。

这篇分两半： **上半篇是完整流程** ； **下半篇是返工最多的三个地方** ，相信也是大家遇到最多问题的部分。

## 先看全流程

**1 锁定文章** 　确定哪一版是最终稿

**2 改旁白 + 定分镜** 　一起确认，不通过不往下走

**3 声音先试听** 　音色对了，完整旁白只生成一次

**4 拿到词级时间戳** 　全片时间基准，后面所有画面都跟它走

**5 切场景** 　按语义切，不按秒数平均切

**6 定视觉系统** 　配色 / 字体 / 构图 / 动作，先定死

**7 做画面** 　用 hyperframe 渲染成视频

**8 自动检查 + 人工看** 　结构、布局、对比度、抽帧

**9 先出低清全片** 　完整看完，再出正式版

关键在第 3、4 步： **声音必须先做完** 。声音一旦确定，后面所有画面的时间点就都被它定死了。倒过来做，返工是灾难性的。

## 第 1 步：文章和视频不是一回事

公众号文章一般都很长，不能直接当配音稿，要先处理：删掉只适合读不适合听的重复说明、长句拆开，还有最关键的一条——

**一句话如果配不上任何画面，它在视频里就是空转，宁可删掉。**

还有个更容易忽略的： **视频顺序不该照抄文章顺序** 。文章按章节走，视频要按观众的理解顺序走——先给结果，再打破误解，再解释机制，最后收结论。

📌 提示词 1｜文章改旁白 + 语义分镜

我要把下面这篇文章改编成竖屏解说视频。

这一步不要写代码，不要生成图片和配音。

第一部分，改旁白：

1\. 前 3 秒直接给结果、冲突或反常识，不要铺垫；

2\. 保留文章主线，不新增文章里没有的事实；

3\. 删掉重复、书面化、只起承接作用的句子；

4\. 长句拆开，避免连续堆名词；

5\. 明确区分：哪些是事实，哪些是我的解读；

6\. 顺序按观众理解路径重排，不要照抄章节顺序。

第二部分，每段旁白后面跟一个画面任务，写清楚：

1\. 观众此刻必须理解什么；

2\. 画面主体是什么，做了什么动作；

3\. 动作结束后，什么状态变了；

4\. 这段是在证明、解释、比较，还是展示状态变化。

如果某句旁白找不到对应的画面任务，直接标出来，我会删掉。

先输出完整旁白和画面任务表，等我确认。

确认之前不要生成配音，也不要生成正式画面。

文章内容：【粘贴文章全文】

## 第 2 步：先把分镜定死，再动手

顺序是：内容结构 → 观众认知路径 → 视觉表达 → 视觉风格 → 分镜 → 审美复查 → **最后才是实现** 。

听起来啰嗦，但它挡住了一个很实际的问题： **AI 很擅长生成，但它不知道什么时候该停** 。不先把风格和结构定死，它每一镜都给你一个"看起来还行"的东西，连起来就是四不像。

📌 提示词 2｜知识视频导演流程

你是知识视频导演 + 信息可视化设计师。

给你一篇文章，先不要写任何代码。按顺序完成：

一、内容理解

最重要的 3–7 个知识点是什么？哪些是事实，哪些是解释？

哪些内容删掉也不影响理解？

二、观众认知路径

不要按文章段落顺序做视频。重新设计理解过程：

问题 → 建立认知 → 制造冲突 → 解释机制 → 举例 → 收束。

三、视觉表达方式

每个知识点先判断结构：概念 / 因果 / 对比 / 流程 / 时间线 /

数量变化 / 问题与解决方案。再选表达方式。

规则：优先选"能帮助理解的"，不为了好看加动画。

四、视觉风格（不要默认 SaaS/PPT 风）

定死：构图、字体、颜色（强调色只留一个）、形状、动作。

同时写清楚哪些动效禁止使用。

五、分镜

每一镜写：目的 / 旁白 / 观众必须记住什么 / 画面概念 /

构图 / 视觉层级 / 动作 / 转场 / 时长。

一镜只解决一个认知问题。

六、审美复查（这一步不要跳）

以美术指导身份逐镜检查：是否真的帮助理解？

是不是为了动画而动画？是否和上一镜太像？能不能更简单？

特别检查：过度使用卡片、箭头、圆角矩形、图标、渐变、淡入；

是不是所有元素都居中；是不是所有镜头长得一样。

发现问题直接改分镜。

七、确认之后，才进入实现。

最终标准：观众应该觉得"这个画面让我更容易理解了"，

而不是"这个画面用了很多动画"。

第六步收益最大。第一版分镜自己看没问题，逼自己以美术指导身份重看一遍，直接发现 **10 个问题** 。

## 第 3 步：声音决定全片所有时间

**声音不是最后盖上去的一层。** 它决定字幕什么时候出现、镜头停多久、每个元素在哪一刻入场。

**先试听。** 从旁白里挑十几秒，只生成这一小段，确认音色、语速、停顿。

**确认之后，完整旁白只生成一次。** 注意是"一次"——因为要的不只是音频，还有同一次请求返回的 **词级时间戳** 。

## 第 4 步：按语义切场景

不要按"每 7 秒一镜"平均切。按 **语义** 切——一段旁白讲完一件事，就是一镜。我这条 98.5 秒切成 14 镜，每镜从 2.96 秒到 12.21 秒不等。

判断一镜是否成立，只看三个问题：

1\. 观众在这里必须理解什么？

2\. 画面主体做了什么动作？

3\. 动作结束后，什么状态变了？

文字飞入、图标漂浮、背景循环，都不能代替这三个答案。

## 第 5 步：画面用 Hyperframe 写

很多人最好奇的： **画面到底用什么做的？**

我用的是 HyperFrames—— **用 HTML 和 CSS 写画面，用 GSAP 写动画，直接渲染成 MP4** 。不是剪辑软件。

**14 个场景是完全独立的文件** ，改第 7 镜不会碰到第 8 镜。编排文件只负责"第几秒放哪一镜"。字幕单独一层盖在最上面，这样场景转场时字幕不会跟着动。

素材三类： **真实截图和成片** （能用真的绝不画假的，14 镜里 9 镜用了）、 **IP 动作库** （下半篇讲）、 **现成组件** 。

**用一个新工具之前，先花十分钟看它有什么，比闷头写两小时划算。**

## 第 6 步：渲染前的三层检查

**第一层，自动检查** ：结构、元素越界、文字对比度、动画回放。

**第二层，抽帧人工看** ：按每镜关键时刻抽静帧拼成联系表。这一步抓到过文字被挡、爪子没对准、书名断行断在奇怪地方。

**第三层，先出低清全片完整看完** 。前两层只能证明"文件没坏"，证明不了"节奏舒不舒服"。

机器检查回答"视频有没有坏"，人工审片回答"视频有没有用"。这两件事不能合并。

下半篇：返工最多的三个地方

## 返工一：做出来了，但像 PPT

第一版渲染完，自动检查全绿。我自己看了一遍，感觉是—— **能看，但像 PPT** 。

### 真因一：动效单一

感觉像PPT在翻页。

参考官方的案例和组件库，选择和生成自己的一套组件库，尽可能包含各种动效场景，以后就不是随机选择，而是从动效库中选择。

官方地址：

https://hyperframes.heygen.com/prompting/overview

https://hyperframes.heygen.com/guides/general-video

### 真因二：底色和素材撞色

整体背景色和视频中的背景色感觉有点太接近了。

我用的底色是暖米白，很雅致。而视频里大量使用的剪纸插画—— **它自己的背景也是暖米色** 。两个颜色明度几乎一样，素材贴上去就 **"融"进背景里了** 。

## 返工二：IP 形象返工率高到离谱

我想让莫影兔在视频里做点事——抬个手、指一下、手里拿个东西。

图片生成会让人崩溃，因为要动态效果，又不是真的视频生成，后面叠加动作效果很难成功。（一把辛酸泪，试过的人都知道）

一张一张按镜头生成，等于 **每个镜头赌一次** 。而且越是"手里拿东西"，翻车率越高——它同时要画对手、画对道具、还要画对两者的接触关系。

想要真正的视频效果，可以生成动画效果的首帧画面，接视频API（比如Seedance）来做，目前成本有点高。回头尝试下开源视频（Minimax H3）生成模型的效果后，可以用这个方案试试看。

### 解法：不按镜头生成，做一套动作库

**一次性把常用动作全做出来，验收通过后固定，以后所有视频复用，按需选择添加新的动作。**

![](https://mmbiz.qpic.cn/sz_mmbiz_jpg/VNBBfVP35HZkKia37ibu5RbR6aI7CIcNeoC3kQyHeX9qI9rQ2U1KWBHtDBlPo5KE82lr8N8yMfZR9m1wJcKcWIOXxdZ4j4pRbteL504hICQ8Q/640?wx_fmt=jpeg)

我这套库目前是24 张： **通用动作 14 张** （待机、讲解、提出重点、指左、指右、思考、提问、质疑、提醒、惊讶、验证、展示空白卡、确认完成）， **场景触发动作 4 张** ， **侧面背面 6 张** 。

全部透明底 PNG， **同一景别、同一身高比例** ——这条很重要，不然镜与镜切换会跳大小。有了库之后，做视频就是从库里挑， **返工率直接归零** 。

📌 提示词 3｜IP 动作库生成 + 验收

【第一部分：锁定不可变化特征】

我提供一张 IP 标准参考图。先看图，把不可变化特征逐条写出来：

角色类型、五官、配饰（位置和左右方向）、服装（图案方向）、

身体比例、手/爪的画法、画风。

写完给我确认。这份清单后面每张图都要对照检查。

【第二部分：生成动作库】

不要按镜头单张生成。一次性生成一套通用动作库：

待机聆听 / 正常讲解 / 提出重点 / 指向左 / 指向右 / 思考 /

提问 / 轻微质疑 / 提醒避坑 / 惊讶发现 / 认真验证 /

展示空白卡片 / 确认完成

另加角度组：严格左侧面 / 严格右侧面 / 左后 3/4 / 右后 3/4 /

完整背面站立 / 完整背面走开

硬性要求：

1\. 背景必须透明 PNG（带 alpha）。不要白底——白色角色抠不出来。

2\. 全套同一景别、同一身高比例，不然切换会跳大小。

3\. 高度 ≥1400px，全身，不要预裁。

4\. 动作手必须完整、清晰、不被遮挡。

5\. 图里不要加文字、卡片、箭头、光效——这些在剪辑里做。

6\. 表情保持在参考图已有范围内，不要夸张情绪。

7\. "展示结果"的动作，卡片保持完全空白，文字后期叠。

【第三部分：逐张验收】

1\. 身份检查：对照第一部分清单逐条比对，一条不符就判失败。

2\. 手/爪检查：有没有变成人类五指、出现对生拇指、

　　增加参考图没有的掌垫？

3\. 肢体数量：耳朵、手臂、腿、脚对不对？有没有融合断裂？

4\. 透明度：四角 alpha 是不是 0？半透明像素有没有残留底色？

5\. 动作可读性：静音看图，能不能一眼看出它在做什么？

给出通过 / 需修订 / 硬失败三档结论，硬失败必须重做后才能用。

不要为了交付把整套标记为通过。

## 返工三：IP 放进去 ≠ 有用

我第一版把 IP 放在结尾，站在结论旁边。做完自己看了一眼：

光站着当背景板没意义啊。

确实。而且问题不在姿势，在 **顺序** 。我原来是 **结论句先出现，然后角色进场** ——这个顺序下，角色是"看着结果的旁观者"。

把顺序反过来： **角色先到场，结论句才被写出来** 。一模一样的素材、一模一样的位置，只是把时间调换了一下，它就成了 **发出判断的那个人** 。

角色在场 = 人在做判断；角色不在场 = 工具在执行。

这条视频讲的本来就是"人负责判断，工具负责重复"。所以角色出不出场，本身就在讲这个道理。每一镜都塞它，这个意思就没了，它就真成了壁纸。

## 写在最后

AI 生成视频还是没有那么稳定的，不管是用即梦的Seedance生视频，还是用Codex做视频。

人对视频的审美可以说才是决定性因素。即使你把组件库都扔给AI让它去选择，它只能做到合格。

把Hyperframe的官网的案例和组建看一遍，自己有基本的认识，哪些风格是喜欢的。可以根据不同的场景做一套自己的组件库，这样视频生成的时候从组件库选择，结果就会稳定很多。
