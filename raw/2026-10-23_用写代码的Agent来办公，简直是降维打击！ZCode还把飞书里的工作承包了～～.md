大家好，我是创意猎人。

上个月我们办了一场 AI 创作工作坊，大家很踊跃，报名的人很多，但是电脑不够了。那么问题来了，我们需要决定是拒绝掉一些粉丝，还是再租几台电脑？而且财务要活动预算表，现场同事要执行手册，总之活又多又碎……

手上的资料也很乱：报名表里面有重复、有退款；有一场地限制；还有一些领导的要求。要是自己做肯定来不及，于是我决定把这摊子事整个丢给 ZCode。

它本来是程序员写代码用的 Agent，写代码要求 AI 聪明、严谨、遵循目标，我发现这些能力放到办公里一样好使。而且我使用过后有一种很明显的感觉：用写代码的 Agent 来办公，在执行力方面差别明显，有种降维打击的感觉。很多原本要来回折腾的活，交给它们处理，变得很轻松又顺手。

接下来我们开始测试：

## 01.

## 一个Prompt，Excel/PPT/Word全搞定

我先准备了三份输入：72 行报名表导出、一份场地与执行约束、一份成品交付要求。

输出的要求也很具体：Excel 要让负责算账的人得到数字结果；PPT 要让领导看清结论快速决策；Word 要让当天到场的同事照着策划执行，三份文件讲的是同一件事，人数、成本和建议必须一致。

## 1.1 用Excel 先把报名人数算对，再讨论能赚多少钱

首先要对名单去重，72 行报名记录，按订单 ID 保留最新记录后剩 60 单，其中 4 单已退款，最后是 56 个有效名额，上午 32 人，下午 24 人。电脑只有24台，所以上午场缺8台。是增租 8 台电脑，还是退掉 8 个名额呢？

具体的任务可以这样交代，换成你自己的活动、培训或项目也适用，参考提示词如下：

```
读取项目中的报名导出、资源约束和交付要求。先按订单 ID 与最新更新时间去重，剔除已退款订单；分别核对两场的人数、设备和人员容量。比较缩减名额与增租设备两案，交付带公式的 Excel 预算、6 页可编辑 PPT 和 2 至 3 页 Word 执行手册。保留原始数据与计算依据，三份文件数字一致，缺失信息标为待确认。保存成品，逐页渲染检查后再交付。
```

这段提示词里，我最建议你保留的是“计算依据”“数字一致”和“缺失信息待确认”等关键信息。把验收条件说清楚，后面的文件才有共同标准。

ZCode比较一下，发现还是增租收益更大。

还可以让 ZCode 用 Excel 做个看板，这样可以随时调整报名人数、电脑价格等变量。

## 02.

## 重复性工作，用Workflow完成

活动办完，还有一件更磨人的事：整理学员反馈。

这次收了 24 份，问卷里有，群聊里也有。麻烦的是，同一个人的意见经常被转发好几遍，24 份里其实只有 20 条是不重复的。人工整理很容易把同一个问题算成好几次，最后得出"大家都在吐槽 XX"的错误结论。

这种又要重复做、又怕出错的活，正适合交给 ZCode 的 Workflow：它会先排好流程，再派几个 AI 分工，一个摘原话，一个分类，一个专门回头挑错。

大家在提示词里带上“/workflow”，或者直接说“用workflow帮我处理XXX”，就可以使用这个功能。

提示词：

```
/workflow 整理 batch-feedback 文件夹内的反馈资料。先展示抽取、按反馈 ID 去重、归类、核验和交付的流程，再运行。证据表保留全部文件的原文与文件名，主题统计只计算唯一反馈 ID。由独立审核 Agent 重读原始文件，核对覆盖、重复、计数和结论，不通过就修订。交付证据表 CSV、主题汇总和两页改版 Word，全部标注模拟资料，并保存工作流供下批资料复跑。
```

最后交给我一份按问题分好类的反馈清单，外加一份下期活动的改进方案，每条建议谁来做、什么时候做都写清楚了：

## 03.

## 高效办公，一定要接上飞书

现在很多公司或者团队，都采用飞书、钉钉、企微来协作办公，平时的办公资料、文档也都放在里面。所以我强烈建议大家把 ZCode 接入你的办公通讯软件，这样 ZCode 就可以直接查看和编辑云文档，效率起飞！

文章末尾我会说具体怎么接入，这里先用几个案例演示。

接着前面学员反馈的案例，如果我们有一份word总结，以后想查"到底是谁提过这个问题"，还得回头翻原始问卷，就很麻烦。所以这次我让 ZCode 顺手建了一张飞书多维表格，把 20 条独立反馈全部写进去，跟进起来就很方便。

```
使用飞书 CLI，把这批资料整理进一个新的多维表格。先读取文件并按业务 ID 去重，再建立或核对字段；保留逐字原文与来源，分析结论单独存放。批量写入后读取全部记录，核对唯一 ID、记录数、原文和分页。以后导入新资料，先查已有 ID，已有记录按明确规则更新，新 ID 才新增，不能把重复导入变成重复数据。
```

ZCode 不光能处理手头已有的资料，还能自己去外面找信息，例如行业动态、竞品更新、开源项目的版本发布，它可以搜索完直接写进飞书多维表格，变成团队随时能查的资料库。

我自己就拿它做了一个选题库，让 ZCode 去读 LangChain、Ollama 等 5 个项目的发布记录，一次整理出 100 条，每条都带版本号、发布时间和原始链接，重复的自动去掉，直接写进飞书多维表格，状态统一标成"未审读"。我打开表格扫一眼，就知道哪些值得写。

```
读取 LangChain、LangGraph、Ollama、AutoGen 和 browser-use 这 5 个公开项目的版本发布记录，各整理 20 条已发布记录，直接通过飞书 CLI 写进一个新的多维表格。筛选按 GitHub 的草稿和预发布标记执行。
```

换成你的工作也一样：做市场的可以收集竞品的上新和价格变化，做投研的可以整理公司公告和行业政策，做运营的可以汇总平台规则更新。

## 04.

## 初次上手 ZCode， 可以按这个步骤顺序

从官网或者点击阅读原文获取最新版 ZCode 安装包：

安装后登录并绑定 BigModel 或 Z.ai 账号，已有 GLM Coding Plan 的，连接对应账号即可使用套餐。

进入客户端左下角个人菜单，在“界面模式”里切到“办公模式”，也就是 Work。

新建一个项目文件夹，把输入的原始资料放进去，再选择模型、添加所需办公插件，交代任务和结果输出要求：

大家可以先拿手头上的一份表格、一份策划方案、一个汇报 PPT 开始使用，给到具体的要求即可。

如果要连接飞书，在插件市场找到飞书 CLI 插件，让它检查现有 CLI、应用配置和登录身份。

或者直接让 ZCode 给你配置飞书 CLI，把下面的提示词发给它：

```
帮我配置飞书 CLI。先检查是否已安装、是否已有应用配置和有效的用户身份；能复用就复用。缺少时按飞书官方流程引导我安装和授权，告诉我在哪个浏览器页面操作。完成后读取我指定的一份测试文档，新建一份测试文档并读回核对，确认读写都通了。不要修改分享权限，也不要发消息。
```

当 ZCode 给你返回一份写好内容的飞书文档，那么，恭喜你，表示这条链路已经走通了。

## 05.

## 手机远程使用：注意区分 Remote Control 与 Bot Channel

任务在桌面跑起来之后，可以从左下角手机图标打开 Remote Control，用手机扫描客户端生成的二维码，或打开对应链接即可快速连接 PC，这样就可以查看任务进度、补充指令了。

需要注意的是，远控任务仍在电脑上执行，电脑要保持开机联网。

如果想从飞书/微信等 IM 聊天里进入工作区，可以在 Bot Channel 中选择飞书/微信，按引导创建或连接机器人，完成扫码配置，再到机器人聊天中发送客户端给出的绑定指令。

## 06.

## 写在最后：ZCode 开始到工位帮你干活了

把以上我最近的工作串起来，ZCode 的价值就很清楚了：以前用 AI，是它写一段、你搬一段。现在你只要把目标讲清楚、把资料给到位，剩下的它自己会调动各种工具解决。

对普通人来说，值得训练的能力也更具体了：把目标讲清楚，把资料组织好，给结果设好验收标准。

像 ZCode 这样的 Agent，让我们有机会少花精力在文件搬运、格式转换和重复整理上，把更多时间留给业务判断、方案取舍和需要自己负责的决定。
