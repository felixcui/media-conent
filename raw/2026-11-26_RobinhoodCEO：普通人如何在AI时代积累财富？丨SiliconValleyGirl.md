## 摘要

Robinhood CEO Vlad Tenev 把“AI 时代怎么积累财富”拆成两个问题：能不能拿到企业成长的收益，以及 AI 能不能替你执行投资策略。第一个问题他的答案是算账：一家以 1 万亿美元估值上市的公司，想让公开市场投资者拿到一千倍回报，估值得冲到 1000 万亿美元——进入时点决定了后续空间，所以别只盯着下一家千倍公司，起点是理解自己持有什么、给学习和长期积累留时间。Robinhood 的回应是 Ventures，让个人也能接触未上市企业；要分清产品结构，RVI 是投私营企业的上市封闭式基金，买的是基金份额而非直接持股，还有费用和流动性风险。第二个问题他说得很克制：不承诺“完全安全”，要先看信息怎么被使用、服务商会不会泄露，再看究竟授予了什么权限。Robinhood 用 MCP 支持外部 Agent 接入券商账户，交易走独立 Agent 账户、用户先转资金 Agent 才能动，读取其他账户不等于能从那些账户交易，逐笔审批默认开启；三者分开是关键边界，但只有限权限，不保证策略正确，也不消除数据风险。正在做的 Loops 让 Agent 定时查市场与持仓、按预设流程提建议，官方页面仍标“即将推出”。

AI 公司不断创造财富，普通人怎样参与？把账户交给 AI，它能替你作出更好的投资决定吗？

在这期访谈中，Robinhood 联合创始人兼 CEO Vlad Tenev 把这两个问题分开了：一是能否拥有企业成长带来的收益，二是 AI 能否帮助人执行投资策略。工具降低门槛，并不自动带来更好的判断。

对工程师、产品经理和创业者而言，后半场同样值得读：Robinhood 怎样让 Agent 承担持续运行的工作，如何判断它是在创造价值，还是只在消耗 token；而一个创始人，又该怎样放下自己曾经坚持的做法。

## 参与AI增长，先看自己能拥有什么

Vlad 对投资的兴趣，来自一段并不轻松的家庭记忆。他小时候离开保加利亚，当地经历了严重通胀。祖父母没有方便可用的证券市场渠道，只能把铜制炊具放在公寓的柜子里储存财富。这让他很早意识到，能不能持有可靠的金融资产，会影响一个家庭的生活稳定。

如今，他关心的是另一种参与门槛：很多企业在上市前，已经完成了很大一段增长。他用一个算术说明区别——一家以 1 万亿美元估值上市的公司，如果还想让公开市场投资者获得一千倍回报，估值就要达到 1000 万亿美元。他想说明的是，进入时点改变了后续增长空间。

Robinhood Ventures 是他回应这个问题的一条路径，希望让个人投资者也能接触未上市企业。这里需要分清产品结构：按官方说明，旗下 RVI 是投资私营企业的上市封闭式基金，买入的是基金份额，并非直接成为其中每家公司的股东；基金也有费用和流动性等风险。

但谈到一个人怎样开始理解投资，Vlad 讲的并不是复杂工具。他 13 岁时，因为喜欢父亲带回家的 Palm Pilot，买了制造商 3Com 的股票。后来公司分拆 Palm，他从持有一只股票变成持有两只，还收到了股东表决材料，真的坐下来读了。

"我开始理解，成为一家公司的所有者和股东，究竟意味着什么。后来很多事情，都可以追溯到买下那一只股票的时刻。"

他建议用自己熟悉的企业建立这种理解，也谈到美国面向儿童的 Trump Accounts，以及通过家庭、企业和慈善捐助让孩子更早接触持有资产的想法。访谈中，他对主持人的孩子解释：你可以购买一家公司的产品，也可以拥有这家公司的一小部分。

他强调的起点，是理解持有资产意味着什么，并给学习和长期积累留出时间。 这与追逐下一家“千倍公司”，是两种不同的思路。

## AI能替你下单，不能替你凭空创造策略

主持人Marina Mogilko 已经有一套自己的配置：一部分资产由顾问管理，另一部分自己决定；AI 帮她追踪账户和关注股票的变化，实际交易仍手动执行。她首先问，把账户接给 AI，安全吗？

Vlad 没有回答“完全安全”。他先谈信息如何被使用，以及服务商发生数据泄露的可能性。至于交易行为，则要看究竟授予了什么权限、让模型执行什么任务，不能只凭“已经连接账户”判断它能做什么。

他介绍，Robinhood 通过 MCP——一种让 AI 调用外部工具的连接协议——支持外部 Agent 接入券商账户，也有面向信用卡消费的连接能力。交易采用独立的 Agent 账户，用户先转入资金，Agent 才能动用；能够读取其他账户的信息，不代表能够从那些账户交易。逐笔交易审批默认开启。

把读取信息、动用资金和批准交易分开，是这类金融 Agent 的关键边界。 独立账户和审批可以限制权限，却不保证策略正确，也不消除数据风险。Robinhood 的官方说明同样提醒，Agent 可能误解指令，或依据不完整、过时的信息作出决定。

Vlad 介绍金融 Agent 的权限边界：独立账户限定可用资金，交易审批默认开启。

他还谈到正在开发的 Loops：让 Agent 定时检查市场和持仓，执行预设流程，提出交易或再平衡建议。这是把编程 Agent 的循环任务带到金融场景；截至 11 月 25 日核对时，官方页面仍把 Loops 标作“即将推出”。

主持人追问：什么提示词才能让 AI 帮自己积累财富？Vlad 把“帮我赚钱”比作“给我做一个能赚很多钱的 App”——要求太泛，得到的往往也很泛。

他认为，如果所有人都使用同样的宽泛要求，即使一度存在超额收益，也很难持续。真正可能形成差异的，是使用者是否有独特判断、接入了什么数据，以及如何把想法表达成可以执行的策略。让模型负责执行，并没有省去这些工作。

## 你需要的是交易助手，还是统筹财务的人

主持人进一步澄清：很多人并不想成为交易员，只是想成为投资者。他们更关心怎样分散配置、多久投入一次，而不是设计一套量化策略。

Vlad 因此区分了几类需求。对于没有特定交易策略、希望委托管理的人，Robinhood 有 Strategies：根据风险承受能力、资金使用时间，以及面对大幅回撤时的反应等信息管理投资；定期入金和单只证券的定期投资，也是另一类现成机制。

Agentic Trading 面向的则更像是“有策略，缺执行能力”的人，希望降低编程和策略实现的门槛。长期投资管理与让 Agent 执行一套交易策略，解决的是不同的问题。

还有一种需求，他认为行业尚未做得足够好：跨账户的“财务管家”。它知道收入和支出，能同时查看退休储蓄、信用卡账单和自主交易账户，提醒哪里支出过多、哪里分配不合理，以及不同账户之间是否需要调整。

主持人举了一个已经发生的例子：她想继续买 Google，但 AI 发现她持有的 ETF 也包含 Google，提醒她整体敞口可能已经偏高。不过，顾问和会计师提出的一些安排，AI 并没有主动想到。她真正想要的，是能结合家庭情况提出问题和建议的服务。

Vlad 认为，熟悉 Agent 开发的人可以尝试自己搭建，但需要大量工作：整理上下文、连接账户、定义任务，并让系统持续运行。大众用户通常不愿意为此写很多提示词，这也正是专门的金融产品仍有机会的原因。他也提醒，通用 Agent 并非专为代人进行金融交易训练。能把账户接起来、定期查询，与提供成熟的全局财务服务之间，还隔着一段产品工作。

## 软件更便宜了，创业为什么仍然难

如果下一代模型直接懂投资，现有软件会不会被替代？Vlad 的回答是，模型之外的应用仍在获得用户，产品层面仍然有创新空间。

代码生产变便宜，会让更多软件进入市场，也让注意力竞争更激烈。对手同样拥有这些工具，因此“更容易写出来”不等于“更容易做成”。他认为，识别真实的人类需求、确认产品确实解决了它，仍是尚未被自动化的工作。

被问到只有少量启动资金、今天会做什么时，他把目光投向医疗服务和实体领域：从就医、支付保险到直接面向消费者的服务，完整体验还有很多可改进之处；机器人也有大量原型，却远未普遍进入建房、施工等场景。他把未来十年的机会，理解为将主要存在于数字世界的智能带入更多行业。

对软件团队，他提出的要求则更具体：不能只自动生成代码，还要继续处理审查、测试和部署。否则，代码生产加快了，后面的人工流程仍会成为瓶颈。

当所有人都能更快写代码，竞争会继续移向需求判断，以及把代码可靠交付给用户的完整流程。 他也提醒，早期采用者的速度优势会逐渐扩散，几年后可能只是行业正常节奏。

至于 AI 是否处于泡沫中，Vlad 并没有给出估值模型。他主要描述 Robinhood 客户在一次市场下跌时积极买入半导体和 AI 相关股票，认为他们对长期前景乐观。客户交易热情反映的是情绪和行为，不能据此证明价格合理。

## 全天候工作的是Agent，验收仍要看结果

Vlad 说，AI 让自己重新靠近了一线工作。大型组织的信息经过多层传递，CEO 很难逐一了解员工正在做什么；现在，他可以借助工具处理这些信息，自己也再次写代码、提交修改，使用技能和机器人。

他对员工提出的“全天候工作”，容易被误读，所以他紧接着作了说明：

"你不应该全天候醒着。每个人都会成为一支自主 Agent 团队的管理者，让它们全天候工作。"

他描述的工具演变是：从补全代码，到代写代码修改，再到加入 Slack、接受任务并持续迭代的 Agent 同事。按他的说法，Robinhood 当年已经推出约 20—30 项新产品或主要产品类别，数量是前一年的两倍多、两年前的三倍多。他认为 AI 是其中的重要因素，团队把资金流转、账户创建等基础工作整理成可重复调用的流程，也帮助了迭代。

营销的进展则更有限。他设想把五六个广告版本扩展成面向细分受众的大量版本，但明确说，团队还没有完全做成营销自动化，仍在试验。AI 视频广告初看很像真人，过一阵子观众又能辨认出生成痕迹；目前，他们觉得静态图片更适合批量组合和测试。

那怎样判断 Agent 真在提高效率？他提出工程团队要同时看三个方面：产出多少、是否正确，以及多快完成交付。只看 PR 数量，可能得到大量带缺陷的代码；只按 PR 或提交统计，又可能鼓励把修改拆得很碎。因此还要结合生产事故或缺陷、修改规模、流程耗时和吞吐量。

谈工程团队的 AI 效率时，他强调结合产出、正确性和交付速度，避免只统计 PR 数量。

Agent 是否值得持续运行，要用交付结果和质量检验，不能用运行时长或 token 消耗代替。 营销也一样：比较 AI 与非 AI 活动的获客成本、客户价值、回收周期和投入产出，新增收益能否覆盖新增成本。

他并不主张取消人工审查，而是让 Agent 先处理大量信息、找出关键问题，使人能审查更大范围、也更有意义的内容。

## 为什么要“解雇过去的自己”

Vlad 回忆，2022 年 Robinhood 经历裁员，股价从上市后高点大幅下跌，市值损失约九成。那时他做过一个练习：假设董事会换来一位优秀的新 CEO，这个人会先清理什么？

这样想，帮助他松开了对过去决策的执着。他以远程优先政策为例：那是自己宣布的做法，后来他认为效果不好，却也面对“承诺无法收回”“会影响招聘”的反对意见。如果换一个新 CEO，大家反而容易接受政策调整。真正卡住他的，有一部分是对显得前后不一致的担忧。

"如果过去做错了，不要让它阻止你现在做对的事。当然，如果总是来回摇摆，那可能也有问题。"

这是他对自己公司的判断，并不是远程办公对所有组织都无效。他也不认为领导力能整套照搬：从 Elon Musk 身上，他学习深入细节、解释事情为什么重要；从 Salesforce 的Marc Benioff 身上，他观察到怎样把价值观连接到年度计划、人员和资金配置，但发现自己不能直接复制整套方式。

对他而言，创始人必须相信自己向团队表达的优先级。 否则，公司价值观写得再好，日常讲话和实际投入之间的差距，别人仍然能感觉到。

## 从新公司学习，分清何时转向

他在 Harmonic 的角色也需要分清：他是联合创始人兼执行董事长，团队由另一位 CEO 管理。这段经历既让他把大公司的经验带给初创团队，也让他看到，一个从第一天就围绕 Agent 搭建流程的 AI 公司，会怎样开展模型训练、强化学习和软件开发，再把这些观察带回 Robinhood。

谈到什么时候转向，他留下了一个与“快速迭代”相互制约的提醒：速度能帮助人尽快放弃无效想法，避免慢慢失败；但不能因为事情比想象中难，就总去找下一个看起来容易的方向。

创业者要分辨的，是困难说明方向不值得做，还是值得做的事情本来就需要跨过障碍。 他承认，这更像一门需要判断力的手艺，很难由一条固定规则替代。

## 写在最后

读完这期访谈，可以先检查自己最想交给 AI 的一件事：目标是否清楚，它需要知道什么、能动用什么，以及你准备怎样判断结果。把权限、目标和验收讲明白，才有机会让自动化变成可靠的帮助。 无论是理解投资，还是改变一项工作流程，都可以从有限范围内的真实尝试开始，再根据结果调整。
