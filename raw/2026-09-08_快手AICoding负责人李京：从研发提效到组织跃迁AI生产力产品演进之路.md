## 摘要

快手AI Coding负责人李京在QECon 2026大会上复盘了AI生产力产品三年演进历程：从2023年代码续写起步，自研CodeFlicker与Kate智能研发工作台，AI代码渗透率突破80%，标杆团队需求交付周期下降约60%。当个人提效触顶后，快手将命题从“研发效能”升级为“AI生产力”，依托Token经济学、统一AI基建与“研发大脑”，直面工具、组织、业务三道鸿沟，把AI从个人写码工具转变。

日前，在 QECon 2026 全球软件质量 & 效能大会上，快手 AI 生产力中心 AI Coding 负责人李京在一场题为《从研发提效到组织跃迁》的演讲中，复盘了快手 AI 生产力产品三年多的演进：从 2023 年的代码续写起步，到 AI 代码渗透率突破 80% 、标杆团队需求交付周期下降约 60% ；当个人提效触顶，他们发现真正的瓶颈已不在工具，而在组织。

快手由此把命题从 “研发效能”升级为“ AI 生产力”，直面工具、组织、业务三道鸿沟，靠 Token 经济学、统一 AI 基建与组织实践，把 AI 从个人的写码工具变成可被调度的组织能力。

演讲视频丨 快手 AI 生产力中心 AI Coding 负责人李京

**01** **渗透率 80% 背后：平台、实践、度量三件套**

研发效能领域有一个固定的三角：效能平台、效能实践、效能度量。快手在 AI 时代给它加上了同样的前缀“AI ×”：底层是沉淀了所有研发数据链路及 Agent 记忆与自学习系统的 “ 研发大脑 ” ，在它的上层是传统工具链与当时已形成的部分能力突破，例如：Team协作平台、三端交付平台、质量平台、运维平台。

![](https://mmbiz.qpic.cn/sz_mmbiz_jpg/ic8BH9EFusn4GwpvAuicsUc7ULWo5QcQjDFaBFteg0cYzmvicFY0xR8BKOKlLRUHQicGtEOd4ezsBFQcnBAcyKiccOp4ZYUiabmnGgVUibRRP68GCU/640?wx_fmt=jpeg&from=appmsg)

先从 Coding Agent 说起。三年前快手从 Copilot 式的代码续写出发，做出自研的 CodeF licker（从最初的代码补全工具到如今的Coding Agent） ：一个全覆盖产品，既有自研的 AI 原生 IDE ，也有适配不同技术栈的 IDE 插件和外部问答系统。它用 S pec 驱动研发场景，用Vibe C oding 驱动泛研发场景，支持自然语言直出、让 Agent 操作浏览器。

![](https://mmbiz.qpic.cn/sz_mmbiz_jpg/ic8BH9EFusn6Fs7rJ04HjWohNDgXhpez8pf7YpKqM5Yk8K5REKM1HN9DeenySM6DwoHLb4lHUyou0eddLnlfYRLyAfVLElWUlpibtDwU3Hw2U/640?wx_fmt=jpeg&from=appmsg)

去年下半年，快手技术团队看到AI Coding领域的三个趋势：

并行化 —— 同时给 Agent 派很多活，产品上支持 Agent W indow ，框架上支持多 Agent 任务模式；

全链路闭环 —— 让 Agent 交付端到端结果，于是做了一系列重型工具，例如 B rowser 工具，能用你的身份、 C ookie 和操作习惯去操作本地 IDE ，还做了 Figma 工具，能在设计稿上选点转码；

自进化 —— 通过长期记忆的漏斗式读取与渐进式压缩，让 Agent 越来越懂你。

再把视角拉高到全链路。K ate 智能研发工作台承载辅助开发、协同开发、端到端自主交付等研发模式，沉淀出一批基于同一套 Agent 框架的垂直领域 Agent ：上下文可以复用，研发过程数据实时回流 “ 研发大脑 ” ，形成知识提炼、记忆更新、效果增强的闭环， Agent 越用越好用。

![](https://mmbiz.qpic.cn/sz_mmbiz_jpg/ic8BH9EFusn49szAHPt7neZxTwSqX25qGxDXL0JMcGlL521dd1FBPI9Uicw3GjWDJ9icANT1p4Rr9GFIGgYzATb8Nw2rC4SzdibrDLvUyuBM8qc/640?wx_fmt=jpeg&from=appmsg)

提效还要可度量。快手把需求 AI 研发成熟度分为L1 辅助、 L2 协同、 L3 自主三个层级，把 AI 能力成熟度定义为 M1 到 M4四个层级。其中M1（概念验证Demo级）、M2（早期试用）、M3（规模应用、准确率大于85%）、M4（完全成熟、不需人工介入）。

![](https://mmbiz.qpic.cn/sz_mmbiz_jpg/ic8BH9EFusn5nNJAt8qPdpyvZvYlEh1H5icV88osrg5sLE7HZZA653S16L6p3ZI5nyzwSE307WZS6UQCEUvyDIYucCK8wglfbTOG1wXuv30EE/640?wx_fmt=jpeg&from=appmsg)

在AI×效能实践的推广上，快手用了 “ 三步法 ”—— 先放开导入，允许自由选择，让大家用脚投票，再把优秀实践孵化成课程和标杆指南，最后做存量渗透与文化宣导激励。

一年实践后的第一阶段结果是：

•AI 代码渗透率超过 80%+

•AI 生成代码占比 30%+

• 标杆团队 L2 需求占比达 20%+

• 需求交付周期下降约 60%

但比数字更有意思的是洞察到了： **AI 是一个透视镜，也是一个放大器** —— 它让协作与数据做得不好的团队更快暴露问题，也让做到极致的团队获得更大的提升，并形成标杆效应。

**02** **三大鸿沟：研发效能的终点， AI 生产力的起点**

做到这里，快手似乎已经找到了从个人提效到组织提效的路径，可以规模化复制了。但随即发现，研发只是业务团队里的一环 —— 写代码只占程序员工作时间的一部分，只推研发变革远远不够。

**研发效能的终点，可能只是 AI 生产力的起点。** 当快手把 AI 带给全员，三道鸿沟浮出水面。

![](https://mmbiz.qpic.cn/sz_mmbiz_jpg/ic8BH9EFusn4xiaHb4FzTIRic6p2eAk4Hogk16ug9bszd9Ejic9No9gSFRxT0ze7HDuX4EOEbRw3pO0OcLkSe3I7q8oUskoE6F1ibYUHP3HsfrYY/640?wx_fmt=jpeg&from=appmsg)

一是工具鸿沟：大厂中厂里 AI 产品 “ 百团大战 ” 、各有利弊；基建层面各团队不断造轮子， Skill 、知识库、 CLI 没有统一标准，很难沉淀。

更现实的是成本 —— **Token** **就是 AI 产品的电力，多一个用户使用，就多一份成本。** 用户量爆炸时成本巨量攀升，而业务老板很难认同这笔 AI 投入对应了业务价值。

二是组织鸿沟： Token 成本怎么分摊、部门之间谁出钱、全员变全栈，动的是组织重塑的利益与部门隔阂。

三是业务鸿沟：业务是非标准化的复杂流程，不是输入一个P rompt 跑一条自动化流程就能拿到绩效；组织变革与业务价值相互耦合，而业务价值又是长周期的，很难像代码生成率那样直观验证。

破局需要三条线并行：

制度上，把 Token 成本变成可量化、可管理的事情；

基建上，成立公司层面的 AI 基建小组；

组织上，自上而下的技术先锋队与自下而上的 AI 布道师并行，再加上公司层面的全民 AI 活动。

**03** **Token** **经济学：把成本算明白，把底座打牢**

今年年初，主流模型能力大爆发， “ Agent 能帮人干所有事 ” 成了全民共识，连运营、财务同学都下载 IDE 自己写代码， Token 用量随之暴涨。

快手的应对是一套 “ Token 经济学 ” ：先限额试点，再推行全员积分制。

![](https://mmbiz.qpic.cn/mmbiz_jpg/ic8BH9EFusn72PYaSPo63aXOtgNrW15TlhjkFOvwbmGdkaAIS3HZ1UMcQxMK2jicdbT5HKMjnfQA1FhzrzpzVziclV3xqfz98VibAerlrVY5hX8/640?wx_fmt=jpeg&from=appmsg)

积分制有几个关键动作：分角色差异化配额；模型积分倍率不同，好模型更贵；自部署模型闲时使用积分打折；阶梯预警与超额审批并存 —— 业务线真有需要可以申请，不让人真正被B lock 。

配额有限之后，反而逼出了基建优化： Skill 可能很耗 Token 、缓存利用率有优化空间、 CLI 有优化空间。 **在配额有限的情况下，成本压力倒逼基建持续优化。**

再看 AI 基建全景。

底层是快手公司统一的模型平台 “ 万擎 ” ，汇聚商业与开源的 SOTA 模型；

上层是各职能的 Skill 与涌现的垂直领域 Agent ，比如快手内部“ 最有名 ”的 Data Agent ，几乎解决了报表配置、数据分析、 OLAP 洞察等场景；

中间是重点 —— Agent OS 层，可以分五层理解：

服务对接层做A uto智能 路由，用小模型把任务路由到 “ 经济、效果好、速度快 ” 的合适模型，并带探活、降级兜底与备份切换；

执行引擎层提供本地执行引擎与云端沙箱；

Agent 层做内核闭环、资金化与安全；

资产层沉淀 CRI 、 Skill 、知识库；

接入层让 Agent 可以被当作 SDK 、 API 、 Skill 或 Service 调用。

资产层重点提两点：

一是 CLI ，一种确定性执行协议：把公司所有工具产品对接上来，配统一 OBO 身份认证和 API 网关统一鉴权控流，让 Agent 能确定性地操作任何工具，比浏览器更稳。

二是 Skill 市场，解决外部引入的安全风险、质量参差与重复建设，打通生产、优化、消费、运营全链路 —— 一句话就能创建 Skill ，经安全评测、流水线编译后一键发布，创建者还能看到使用量与使用部门。

目前快手内部已有 200 多个精选 Skill ，覆盖十多个领域，日均调用量保持高频增长。

产品层的本质变化也值得记住： **从功能完备、标准输出的工具，变成一个真正懂你的 AI 工作伙伴** —— 它学习你的记忆、习惯与工作场景。

客户端架构上，云端的控制面与网关负责会话管理和调度，本地电脑、云服务器甚至闲置的 Mac Mini 都能作为执行节点挂载。 **Agent** **不再是你电脑里的个人助手，更像一个随时可以被调度的协作者。**

Agent 时代还需要新的观测。传统监控看报错、白屏、性能，现在要盯 Agent 循环输出、空回复、缓存利用率下降这类新异常，要做成本归因分析，还要沿客户端到供应商的全链路排障，甚至用 AI 做智能定位、智能归因，把数据关联到代码仓库自动修复。

**04** **组织跃迁：从超级个体到 AI 原生团队**

从个人到团队，是快手 AI生产力 产品的一条重要演进线。如果将AI Coding产品CodeFlicker直接进入团队，会存在信息与成员对不齐、没有全局知识留存、不认识协作分工的问题，于是 CodeFlicker 演进出了团队版-“团队空间 ” ：将会话、任务、技能、知识资产按团队隔离。

![](https://mmbiz.qpic.cn/sz_mmbiz_jpg/ic8BH9EFusn6GRmAZctcXI90gMXica4UJzdsGl1FFOm7icg2iaS56eq5Irt0AQNtMB0dNV4dFmlGsZwuLwia3rFjlIY1MXSRJuiaQX24rvvI7hdok/640?wx_fmt=jpeg&from=appmsg)

从CodeFlicker到MyFlicker，在 技术上重点要解决三个问题：安全（权限管理、隔离策略，防止 Agent 用错身份、引用错知识）、环境（独立环境执行与上下文复用并存）、成本归属（算个人、团队还是组织的钱）。

效果如何？据悉，该产品在一些标杆团队， AI 在内容理解、审核达标等真实业务场景中带来数十倍提效和几十个百分点的业务效率提升。

公司层面的变化也很有意思。李京举了一个例子，今年快手司庆的 “AI 贪吃蛇大作战 ”游戏 ：用 AI 写一个贪吃蛇策略，部署上线，两个策略实时对战，几千人在线投票。

**很多之前没写过代码的同学真的开始写代码了** —— 用自然语言描述策略、一键部署；而对战系统、投票系统、后台管理系统，全部由运营同学自己交付，研发同学只在上线前做了量级保障。 **运营同学开始交付需求，不再只依赖研发团队上线东西。**

对AI×组织的未来形态，快手还在探索，李京给出了自己的畅想：要将AI生产力进入一个团队，先孵化专家的 Skill 、建立领域知识库，再培养团队的 AI 专家；角色上， FDE 、 PDE 、全栈工程师正在涌现，未来每个人可能配一个或多个 AI 员工，组织协同会变得更自主，很多领域甚至可以由 AI 专家直接撑起来。

最后，他分享了自己和团队的三条经验，想转 AI 原生的团队可以借鉴： **团队负责人首先先成为一个 AI 超级个体，才能带动团队；团队要先 AI Native 化，才有可能做出 AI Native 的产品；只有 AI 业务真正跑起来，才能加速组织层面的 AI 进化。**
