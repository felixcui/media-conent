## 摘要

模型能力正趋同，Agent 能调用什么数据源才是决定任务质量的新分水岭。AIsa 是一个为 Agent 统一接入外部数据和服务的 API 平台，已聚合 5000 多个数据源。作者以竞品调研为例：接入后 Codex 可自动调用 Similarweb、X、Reddit 等专业数据，报告信息密度大幅提升；平台还支持费用预估确认与预算控制，避免 Agent 乱花钱。

模型正在趋同，Agent 能调用的外部资源才是新的分水岭。

这个判断，是我最近用了 AIsa 之后的感受。 **AIsa 这个产品很有意思， 它是一个专门给 Agent 接入外部数据和服务的统一 API 平台。**

我也是刚开始用没多久，说实话，真有点相见恨晚。目前平台已经接入了 5000 多个 API 和数据源。

![文章图片](https://mmbiz.qpic.cn/sz_mmbiz_png/iagroyM7YaBnjwooOx4RScp2t4icSWpkdwFTMtJh6REBiaqOGBYbTD34FS69pdUlTF9xY1FDyBPibVVrIAxfJJA15KowCJlP2ABdMcIClnyPBzE/640?wx_fmt=png&from=appmsg)

我只需要让自己的 Agent 接入 AIsa，后面 Agent 在执行任务的时候，就可以根据需要直接调用这些第三方数据。

**因为现在无论用国外的 Codex、Claude Code，还是国内的豆包工作、WorkBuddy，你会慢慢发现，很多基础任务大家最后做出来的东西其实已经大差不差了。**

**真正拉开任务质量差距的，往往是 Agent 能不能访问到足够专业、可靠的数据源。**

举个非常简单的例子。我想做竞品调研，让 Agent 帮忙分析一下我们的对标大会 AI Engineer。

这么和大家说吧，我前后两次用的都是 Codex，模型也都是 GPT 5.6 Sol，但有没有接入外部数据源，最后出来的分析报告差距非常大。

因为做这类 Deep Research，Agent 默认还是主要依赖 Web Search。

**它肯定能找到官网、媒体报道和各种公开资料，但真正做竞品分析很重要的一些数据，比如网站流量、SEO 表现、X 上用户讨论，它根本拿不到。**

大家看，这是没有接入外部数据源的情况下：

接入 AIsa 之后，能拿到的数据一下就多了。比如网站流量可以去 Similarweb 查，用户的反馈可以取 X 和 Reddit 等等社媒上搜索。

最后做出来的竞品分析，信息密度肯定会高很多。

下面这个是执行过程中，Codex 给我算出来的调用费用。 **它准备使用 X、Reddit、YouTube 的高级检索功能，所以会先把预计费用列出来让我确认。**

因为我刚开始用，还是有点怕 Agent 乱花钱，所以提前给 AIsa 设置了预算。只要超过预算，它就会过来找我确认。

后面查完社交媒体之后，Codex 又准备去 Similarweb 查网站流量，也一样先把费用列出来，等我确认之后再继续。

确实，最后的竞品报告里已经有这部分信息了。 **我觉得对于所有团队来说，竞品调研报告里，流量这些信息肯定是必要的吧。**

我知道大家现在用 Agent，肯定已经非常熟悉 Skill 了。

Skill 我也写过很多次。它本质上就是把过去的经验和流程固化下来，让 Agent 下次遇到类似任务的时候，直接按照这套方法执行。

**但我越来越觉得，真正决定一个任务最后能做到什么程度，除了 Skill，还有一个特别重要的东西，就是数据。**

我们以 Codex 举例子。

最底层是模型，往外一层是 Harness，Harness 里面再接入各种工具。模型负责理解和判断，Harness 负责组织整个任务，工具负责获取信息、执行具体动作。

再往外，就是各种外部的数据源和服务。

这部分其实特别重要。 **因为大部分真实任务，如果没有充足的数据，前面的 Skill 写得再好，最后也很难做出靠谱的结果。**

在知道 AIsa 之前，我其实已经给自己的 Agent 接了很多外部数据源。比如搜索，我单独买了豆包的搜索服务。X 的数据我自己接，YouTube 视频转文字，我也单独买过服务。

基本上就是缺什么接什么。 **每接一个服务，都要去对方那里注册账号，申请 API Key，然后接进自己的 Agent。** 能用当然能用，但整个过程非常琐碎。

AIsa 把一大批 Agent 常用的数据源和服务统一到了一个 API 入口里。

**我只要在 Agent 中接入 AIsa，后面它需要查 Similarweb、X、YouTube，或者调用其他服务时，就可以根据任务自己找到对应的资源直接调用，不需要我再一个个单独接 API。**

最典型的就是 Similarweb。

像 X 这类数据，其实大家自己接也不算困难，费用也没有那么高。但 Similarweb 这种专业数据服务，对我们这种小公司就很尴尬。

我只是偶尔需要查几次竞品网站的流量、关键词、用户来源，不可能为了这点需求专门采购一整套企业服务。

所以以前真要查竞品，我们的土办法就是直接去闲鱼搜 Similarweb 会员，临时买一个，然后自己登录进去查。

但这种方式并没有解决 Agent 怎么调用数据的问题。

**网上虽然也能找到一些所谓的 Similarweb API，但很多其实是第三方镜像或者爬虫采集的数据，来源和更新时间都很难确认，拿来做正式分析还是不靠谱。**

我刚刚专门确认了一下，AIsa 这里接的是 Similarweb 官方 API，这点对我来说非常重要。

因为这就解决了我之前最拧巴的问题：竞品调查本来已经交给 Agent 了，但因为它拿不到 Similarweb 数据，我还得自己买会员、登录后台、截图，再把数据交给 Agent 继续分析。

**本来想把整件事交给 Agent，结果人又被塞回流程里了……**

现在接入 AIsa 之后，Agent 可以根据任务需要直接调用 Similarweb API，人在预算和权限节点确认就行，不需要再手动查数据、搬数据。

我们再跑一个 Case，同样调用 Similarweb，让它看看这个网站当前的 SEO 表现。

大家看下面这张截图，Codex 规划得很清楚。它先把官网和公开搜索能拿到的信息查一遍，再根据缺口去调用 Similarweb。

**毕竟 Similarweb 是付费的，所以只查必要的数据。**

即使我写了预算不受限制，它在收费查询前也会先给出最高金额。

这是最后的预算。如果觉得高，可以继续和 Agent 沟通。

大家也可以拿自己的网站跑一下。 **像我们自己的产品，一跑还真发现了不少很低级的问题。**

这是最后的审计报告：

当然，也可以检查 GEO 的情况：

下面我把这两天我们内部做 SEO、GEO 和竞品流量分析时常用的一些提示词整理出来，大家可以直接拿去跑。

**这类任务一般都需要同时查搜索、DataForSEO、Similarweb、Reddit、X、Perplexity 等好几个数据源，所以最好接入 AIsa。**

**SEO 全站体检**

请检查这个网站当前的 SEO 表现。 **分析网站结构、核心页面、主要关键词、搜索排名、竞品覆盖和内容缺口。**

先使用官网和公开搜索完成基础判断，再根据缺失信息调用 DataForSEO、Similarweb、Ahrefs 等数据源。

最后告诉我最应该优先修复的 5 个问题，并推荐 10 个值得新增的页面。请按照影响程度和修改成本排序，不要只给通用建议。

**竞品流量分析**

请分析这个产品，并识别 5 个最主要的竞品。 **比较它们最近的网站流量、增长趋势、主要流量来源、搜索流量、核心关键词和内容渠道。**

找出哪些竞品增长最快，并继续分析它们的增长主要来自哪里。最后告诉我最值得研究的 3 个竞品、它们分别靠什么获得流量，以及有哪些方法值得我们参考。

**竞品内容缺口**

请比较这个网站和 5 个主要竞品的内容布局。

检查它们在 Google、博客、YouTube、Reddit、X 等渠道主要覆盖了哪些话题，找出竞品已经覆盖、我们还没有覆盖的内容，以及有明显需求但目前内容供给比较弱的话题。

最后推荐 20 个值得新增的内容选题，并结合潜在流量、竞争程度和产品相关度排序。

**关键词机会挖掘**

请围绕这个产品挖掘值得争取的搜索关键词。除了行业大词，也重点寻找高购买意图词、长尾问题、竞品对比词、替代方案词和最近开始出现的新搜索需求。

**对每个关键词判断搜索意图、竞争程度和当前主要排名页面，并告诉我最适合制作什么页面。** 最后筛出最值得优先做的 15 个关键词。

**竞品增长异常分析**

请分析这 5 个竞品最近 6 个月的网站流量和搜索表现，找出明显上涨或者下跌的时间点，再继续调查当时发生了什么。

**可以结合关键词变化、新增页面、外链、产品发布、Reddit 和 X 上的讨论一起判断。** 最后告诉我哪些竞品出现了明显增长，增长可能来自哪里，以及有哪些动作值得我们继续研究。

无法确认的原因请明确说明，不要强行下结论。

**GEO / AI 可见度检测**

请检查这个品牌和 3 个主要竞品在 AI 搜索中的可见度。围绕用户真实可能提出的问题进行测试，包括品类推荐、产品对比、使用场景、替代方案和购买决策。

分析哪些问题会提到我们，哪些只会提到竞品，AI 经常引用哪些网站和页面。最后找出我们目前最大的 5 个 GEO 缺口，并给出具体的内容改进建议。

**从竞品数据反推 GTM 机会**

请研究这个产品和 5 个主要竞品，结合网站流量、搜索关键词、用户评价、Reddit、X 和内容渠道，寻找目前还没有被很好满足的需求。

重点关注用户反复抱怨的问题、已经有搜索需求但产品供给不足的场景、竞品流量很高但体验较差的功能，以及最近新出现的需求。

最后给出 5 个值得测试的切入方向，并说明背后的数据依据和最简单的验证方法。

以上这些思路，希望对大家有帮助。

其实我越用越觉得，AIsa 这个产品有点像 Agent 的淘宝。它做的事情，就是给 Agent 执行任务准备各种生产资料。

淘宝是我们自己上去买东西。 **Agent 也一样，在执行任务的过程中，它可能发现还缺一份 Similarweb 的数据，或者需要调用某个付费 API。**

以前这些东西都得我们自己提前采购、自己接入，现在 Agent 可以直接在 AIsa 里面找到，然后按需调用。我不就是先往里面充了 50 美金，它需要的时候自己花就行了。

这件事情其实也让我重新思考很多 SaaS 的价值。

当越来越多工作直接通过 Agent 完成，过去那些主要面向人设计的 GUI，重要性肯定会下降。但很多 SaaS 真正积累下来的数据、能力和工作流，依然非常有价值。

**所以这些 SaaS 完全可以把自己的 API、CLI 或者 Skill 开放出来，让 Agent 直接连接。**

但如果未来成千上万家 SaaS 都这么开放，我们不可能让自己的 Agent 一个一个去接。每家都注册账号、申请 API Key、配置权限，最后又会变成一件特别麻烦的事情。

所以我感觉，往后一定会出现 AIsa 这一类产品。它把这些原本分散的数据和服务集中连接起来。
