## 摘要

作者开源了一款名为x-scan的X（推特）自动扫描工具，旨在解决用户手动刷推时收藏易丢、难以沉淀的痛点。该工具能自动抓取For You信息流或按指定关键词搜索推文，通过内置词库智能筛选AI相关内容，并利用Tweet ID精准去重，最终将推文详情与热点速览保存为Markdown文件，方便导入知识库进行搜索与复盘，实现省时省心的自动化信息整理。

Hello啊朋友们，我是Simonlin，用通俗易懂的语言，手把手带你玩转AI，提升10倍效率！

我最近把自己一直在用的一个 Skill 开源了，它叫 x-scan，是一个可以交给 Agent 安装和调用的 Skill。由于里面有一个负责实际扫描的 Python CLI，所以也可以单独在终端里运行。

虽然名字很朴素，甚至有点像某个程序员凌晨两点随手起的（

而且功能倒也不复杂，打开 X，往下刷几轮，把推文抓下来，按 AI 相关关键词做初筛，去掉已经看过的，再保存成 Markdown。

但我自己用了几天以后，发现它解决的不是“怎么爬 X”这个问题，它解决的是另一件更烦的事。

我明明每天都在看 X，可看完以后，真正值得留下来的东西，还是得靠自己记。

刷到一篇论文，先收藏，看到一个工具，发到群里，发现一个有意思的工作流，想着晚点再研究。

然后晚点就变成了下周，下周就变成了“我当时到底在哪看到的？”

所以，我给自己做了一个扫描器。

它最直接的卖点，就是“省心，省事，省时间”。

省下我自己动手刷推特、反复收藏、复制链接和整理资料的时间，从而解放我多余的时间去做其他的事情。

这次把它开源出来，地址放在这里：

## 一、它到底能帮你做什么

![Image](https://mmbiz.qpic.cn/mmbiz_jpg/gBevQ6puE7C30AjHB6u1UZMED9uEmma3d40BnUjgk4Jhg0iciazZn4IiaF1UC9iav5R1GmdWSldsDGB3nx4bSLAIcSjtxzSfYqyT43jn07ECuxE/640?wx_fmt=jpeg&from=appmsg)

x-scan 目前主要做五件事。

第一，扫描 X 的 For You 信息流。

也就是你平时打开 X 以后，系统给你推荐的那一页。它会通过专用的 Chrome 浏览器连接到 X，自动往下滚动几轮，把当前页面加载出来的推文提取出来。

第二，搜索关键词。

比如你想看 Claude Code、Agentic Engineering、Graph Engineering、OpenAI，直接把关键词交给它，它会进入 X 搜索结果页，把相关推文抓下来。

第三，筛选 AI 内容。

For You 信息流什么都有。

有人发股票，有人晒猫，有人讨论房价，还有人认真研究今天要不要减肥。

x-scan 会用一组中英文关键词过滤内容，比如 AI、Agent、LLM、Claude、GPT、自动化、工作流、MCP、开源、上下文工程等，把更可能和 AI 相关的内容留下来。

它会帮你把明显不相关的东西筛掉，让你不用从几十条内容里一条一条翻。

第四，按 Tweet ID 去重。

这点看起来很小，但实际很重要。

因为同一条推文，有时候会出现两个地址。

一个是下面这个地址。

```
/status/2078160365276319826
```

另一个是下面这个地址。

```
/status/2078160365276319826/photo/1
```

如果按完整 URL 判断，它们会被当成两条内容。

程序就会非常认真、非常规范、非常没有感情地，把同一条推文保存两遍。

x-scan 现在按稳定的 Tweet ID 去重，所以这两个地址会被认成同一条推文。

第五，保存成 Markdown。

每次扫描之后，它会生成当天的文件，里面有扫描摘要、推文正文、作者、时间、浏览量、点赞、转帖、书签、媒体和原文链接。这里的「摘要」不是大模型重新写一遍文章，而是把筛选后的内容按浏览量排序，再截取每条推文的开头，整理成热点速览。当前版本还会对正文高度相似的推文做保守去重，避免前五条热点被同一类内容占满，但完整推文仍然会保存。

你可以把它放进 Obsidian，也可以放进自己的知识库。

这样下来，它就不再是“看了就结束”，而是变成了一份可以继续搜索、整理和复盘的资料。

## 二、我真实跑了五轮，效果怎么样

为了不把“理论上可以”写成“实际上很厉害”，我在自己的 X 页面上跑了五轮 For You 扫描。

结果是这样：

它做的事情，其实很简单，就是“抓”。

从我当前能看到的页面里，抓到了 7 条独立推文，按 AI 相关关键词筛出 4 条，再按浏览量做了一个热点速览，最后保存成 Markdown。

但说实话，这已经比我自己刷完以后只剩一句“刚才有个东西挺有意思”强多了，至少它把东西留下来了。

而且这次真实运行还暴露了一个小问题。

X 里的推广内容，页面结构和普通推文不完全一样。x-scan 原本按照普通推文的页面规律去找作者，遇到一条推广内容时，先读到了头像的链接，却没有读到用户名，所以作者名显示为空。

这不是那条推文没有作者，而是识别规则没有覆盖这种特殊卡片。我把原始页面结构找出来，调整了识别规则，才把作者名补回来。

修好作者名以后，我又发现这张推广卡片没有提供发布时间。既然页面没有给出时间，就不能猜一个时间填上去，最后只能如实标记为“推广内容”。

这也是我现在越来越看重这种 Skill 的地方。

它不是跑完一个漂亮数字就结束了，而是能把具体哪一块识别错了暴露出来。发现问题以后，可以继续修；修完以后，结果也能留下来核对。

## 三、它为什么不用 X API

很多人看到这里可能会问，为什么不直接调用 X API？

因为 X API 对普通个人用户并不总是友好，权限、额度、价格、认证方式....哪一样都够让人先去倒杯水冷静一下。

这太麻烦了，所以x-scan 走的是另一条路。

它通过 Chrome DevTools Protocol，也就是 CDP，连接一个专门的 Chrome 浏览器。这个浏览器有自己的 Profile，和你平时使用的主 Chrome 分开。

流程大概是这样：

```
启动独立 Chrome
→ 打开 X
→ 复用登录状态
→ 滚动页面
→ 读取已经显示出来的推文
→ 保存结果
```

第一次使用时，你需要在这个独立浏览器里登录一次 X，之后 Agent 就可以帮你安装依赖、跑测试、执行扫描。

不需要把主 Chrome 的 Cookie 复制出来，也不需要把密码交给脚本。

这件事我专门做了隔离。

因为一个工具再方便，如果它为了扫描 X，顺手把你主浏览器的页面切走，或者误操作了正在编辑的网页，那就不是方便，是给自己找麻烦。

我自己就遇见过这样的问题，说多了都是泪啊～～～

现在 x-scan 会检查 CDP 端口对应的浏览器进程和 Profile，端口如果被其他浏览器占着，它不会直接连接，而是报错退出。

这类保护措施可能不如“跑起来就行”那么爽，但真的遇到一次误控主 Chrome，你就会觉得它非常有必要。

## 四、交给 Agent 安装，能不能少折腾一点

我开源它的时候，特意考虑了一个现实。

现在很多人不会自己打开终端，一条一条复制命令，他们会直接对 Agent 说一句话：“帮我把这个 Skill 装上。”

所以仓库里不只是放了一个脚本，而是把一个 Skill 需要的说明、依赖和测试都放在一起。

里面有安装说明、依赖文件、离线测试、使用示例、环境变量说明和故障排查。

Agent 拿到仓库以后，应该能够自己完成这些事：

```
克隆仓库
→ 创建或选择 Python 环境
→ 安装 websocket-client
→ 跑 8 个离线测试
→ 执行 --help smoke test
→ 检查 Chrome 和 CDP 环境
→ 首次运行时提示登录 X
```

安装过程里真正需要人手动做的，主要是第一次在独立 Profile 登录 X，这一步不能省，也不应该省。

除此之外，扫描可以这样运行。第一次安装时，先在仓库目录执行：

```
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

确认测试通过后，再运行扫描：

```
.venv/bin/python scripts/xscan.py --mode feed
```

搜索关键词可以这样运行。

```
.venv/bin/python scripts/xscan.py --mode search --query "Claude Code"
```

如果想看最新结果，可以加上 --latest。

```
.venv/bin/python scripts/xscan.py --mode search --query "Graph Engineering" --latest
```

它还支持设置独立的 Chrome Profile、CDP 端口和输出目录。

不同电脑的路径不一样，不需要改代码，设置环境变量就行。

## 五、它现在能达到什么程度，不能达到什么程度

![Image](https://mmbiz.qpic.cn/mmbiz_jpg/gBevQ6puE7AuVfSbw28naUuT70392djElFbqa9eMkYTDTic9WQI3bdZy9ejSbqriaibzAMgajyUpQdqHibKrRt7aja2KiaJbf8GT5CVNuW8pg3iaQ/640?wx_fmt=jpeg&from=appmsg)

我觉得这个问题要说实在一点。

x-scan 不是一个云端舆情系统，它不会替你全天候监控全网，也不会保证抓到 X 上所有内容。

它看到的，是当前登录账号在 X 页面里实际能加载出来的内容。

它能按关键词过滤，能按浏览量排序，还能把热门推文整理成一段摘要，但不会自动判断一篇文章是否值得你花两小时读完。

所以，它更像一个勤快的资料助理。

每次运行帮你把页面刷一遍，把可能相关的东西捞出来，去掉重复项，留下原文链接，再放进你的知识库。它本身不负责创建定时任务，定期运行要交给外部的 Agent 或 cron。

毕竟真正的判断，还是要人来做。

比如我们在搜索模式下，按照关键词搜索到的相关推文，x-scan 可以把内容抓出来，但它不会自动知道哪一篇论文值得深入核对，也不会自动替你判断这个兄弟是不是在吹牛逼，又或者是引流。

不过这不是它的失败，我本来就不想做一个替我假装判断一切的黑盒。

我更想要的是一个透明的中间层。

它负责把信息从时间线搬到我的工作台。

我负责决定哪些东西值得留下。

## 结语

我一直觉得，很多 AI 工具最后没有用起来，不是因为它们能力不够，而是因为它们没有进入真实工作流。

你今天试了一下，明天换了一个页面，后天又忘了结果存在哪里。

工具就这样慢慢消失了。

x-scan 这次开源，对我来说不只是把一段脚本放到 GitHub 上，更像是把我自己每天会用的一个 Skill 和一小段工作流，整理成一个别人也能安装、测试和修改的东西。

它现在能做的事情很具体。

扫描 X。筛 AI 内容。按 Tweet ID 去重。保存 Markdown。交给 Agent 安装，也能知道哪里报错。

这听起来没有什么惊天动地的地方。

但很多真正能留下来的工具，它本身就不需要多么“惊天动地”。

它们只是每天替你省掉一点重复劳动。

省掉一次“我刚才在哪看到的”。

省掉一次重复滚动和复制。

省掉一次把同一条推文存两遍。
