# AI Coding 已经遇到瓶颈了。

**作者**: 阿颖

**来源**: https://mp.weixin.qq.com/s/rLnwvJwfdXRFm0lg_j5YAw

## 摘要

AI Coding虽能提升编码效率约30%，但因需求分析、测试、部署等环节未同步优化，公司整体交付效率提升有限。网易智企因此升级CodeWave SDD为AI软件交付团队，将需求分析、产品设计、架构、开发、测试等角色Agent化并协同工作，推动全流程Agent化，使效率提升从个人扩展到团队。同时企业应关注整体交付产能而非个人节省时间，最终实现同样人力交付更多项目，转化为收入与利润。

这周听了网易智企关于 AI Coding 的一些反思，非常有启发。他们对 CodeWave SDD 进行了全面升级，新的定位是 AI 软件交付团队。今天想写写我的收获。

**其实这也是最近一段时间，我经常和一些研发负责人、创业者聊到的话题。**

现在 AI Coding 已经相当普及了，程序员基本都用上了 Codex、Claude Code，或者其他 AI Coding 工具。

**AI Coding 至少可以让开发提效 30%，但放到整个公司的经营层面，最终的效率提升可能就只剩下个位数了。**

******#01******

**AI Coding 的瓶颈**

为什么会这样？

因为一个软件项目，除了 Coding，还涉及需求分析、产品设计、技术架构、接口联调、测试、部署等大量工作。

现在代码确实写得越来越快了，但其他环节的工作方式，以及不同环节之间的协作流程，其实并没有发生太大变化。

**软件开发链条上，每个角色都在用 AI，但仍然是各干各的。** 这些工作并没有被很好地组织起来。

所以，AI Coding 虽然提高了单个环节的效率，但整个软件项目的交付速度，并没有同步提高。

**网易的思路是，既然单纯提高编码效率还不够，那要想让整个软件开发流程的效率大幅提高，就得把更多环节 Agent 化，再把这些 Agent 有机地组织起来。**

具体来说，就是把需求分析师、产品经理、架构师、开发工程师、测试工程师等角色，分别做成 Agent，再组成一支完整的软件交付团队。

从理解需求到最终发布，按照软件工程的流程，让不同的 Agent 协同完成任务。这样才有机会把 AI 带来的效率提升，从程序员个人扩展到整个软件开发团队。

******#02******

**老板在乎什么？**

另外，网易还有一个判断，对我特别有启发。

**从企业经营的角度来说，其实没必要整天盯着开发人员节省了多少工作时间，更应该关注整个团队的交付产能。**

因为个人效率提高了百分之多少，说到底，这些都只是局部效率指标。

比如一家软件公司，程序员写代码的速度提高了 30%，但需求还是需要反复确认，测试和验收还是要排队，原来两个月才能交付的项目，现在还是需要两个月。

那个人节省下来的时间，就未必能真正转化成公司的交付产能。

**所以，作为老板，更关心的是，同样一批人，原来一个月只能交付三个项目，现在能不能交付四个、五个？** 这样就有可能转化为公司的收入和利润。

******#03******

**全流程 Agent 化**

网易的 CodeWave SDD AI 软件交付团队，说白了，就是把整个流程全部 Agent 化。

假设我们要开发一套进销存管理系统，按照传统的软件开发流程，需要先分析需求，再设计产品原型、技术架构，然后编写代码、测试，最后部署上线。

CodeWave 会把这些工作交给不同的 Agent 来完成。

**1）首先是需求分析。**

上传需求文档之后，需求分析 Agent 会先阅读整个文档，然后看看哪些地方没说清楚。比如，采购员、销售员和管理员分别有哪些权限？库存不足时应该怎么处理？

采购审批需要经过哪些步骤？

这些问题，过去都需要产品经理和业务反复沟通。 **现在 Agent 会主动提问，一步步梳理需求，最后整理成一份结构化的文档，也就是 Spec。**

![文章图片](https://mmbiz.qpic.cn/mmbiz_png/iagroyM7YaBmM4J8n8nn2tS08RkrLcAq67KgbSyScOgF029f5FCIhr8PfkKs9ibEQ3yazaErLnKhKibUQd5egy0FzkzNSncAFApbUbSnHtdzUY/640?wx_fmt=png&from=appmsg)

**2）接下来是产品原型设计。**

产品设计 Agent 会根据 Spec，直接生成高保真的产品原型。比如首页看板、采购管理、销售管理、库存管理这些页面，都可以先做出来。

业务觉得哪里不合适，可以直接在界面上圈出来，或者通过对话提出修改意见。

这一步挺重要。 **因为对于很多业务人员来说，别说审查了，光是把几十页的需求文档认真看完，可能就挺费劲。**

但如果直接看到产品界面，哪里不符合预期，反而更容易发现。

**3）然后是技术设计和开发。**

原型确认以后，架构设计 Agent 会继续完成技术架构和数据模型的设计。开发 Agent 再根据技术方案，把整个项目拆解成具体的研发任务，逐项编写代码。

![](https://mmbiz.qpic.cn/mmbiz_png/iagroyM7YaBm2zPX4rq11x99IibjfLARSqUDF1S8MAuXjvSTQJpfctrHLAvewIraSEmJYQEJSQB685F5NKCH9nEicjYb6kBzBYrLq739Ywpl6Q/640?wx_fmt=png&from=appmsg)

4）最后是测试和部署。

**代码完成以后，测试 Agent 会根据前面确认的 Spec，自动生成测试用例。** 如果测试没有通过，就尝试修复问题，然后重新测试。等到测试通过，再进入最后的编译和部署环节。

当然，最终交付的软件仍然需要人工验收。

![](https://mmbiz.qpic.cn/mmbiz_png/iagroyM7YaBklANLQxibJqrtDlXUcD9EC9YWFk2dRveF5bb1OtRibfb9kHRgnd04PZibrqYbwLutNWR38ibX8MNh6gNibSUT9C3vYawJys2EnJibRk/640?wx_fmt=png&from=appmsg)

大家应该能感觉到，过去这些工作分散在不同岗位，每完成一个环节，都需要人工沟通、协调，再交给下一个人。

现在，CodeWave 尝试让不同的 Agent 按照统一的流程连续完成这些工作，减少中间的等待和反复沟通。

******#04******

**规格驱动开发和 Harness**

不过，讲到这里，还有一个很重要的问题。

这么多 Agent 一起工作，怎么保证它们对需求的理解是一致的？ **尤其是前面的 Agent 一旦理解错了，后面的 Agent 很可能跟着一起出错。**

这其实也是传统软件开发过程中，经常遇到的问题。

我平时和同事，或者跟 AI 沟通的时候，也经常有这样的体会。明明觉得自己已经交代得很清楚了，但实际上，脑子里还有很多默认的前提和细节，没有真正表达出来。

**对方也觉得自己理解清楚了，结果做出来以后才发现，我们俩想的根本不是一回事。**

一个人尚且如此，更何况是一群 Agent 协同开发一个复杂的软件项目。

**所以，CodeWave 还有一个很重要的设计，就是 SDD，规格驱动开发。**

![文章图片](https://mmbiz.qpic.cn/mmbiz_png/iagroyM7YaBmCNg13JbPeCP6npnls5MI5d77VAqHQXSxia6oHa8ibicgsLOrLDVxAqfJj0PFAVgcmtkeBnOWhiaMITjN8zhysQWaoMnlBh4aXcDc/640?wx_fmt=png&from=appmsg)

简单理解，就是在正式开发之前，先通过需求分析 Agent，把客户没有讲清楚的地方尽可能澄清，再把这些需求整理成一份结构化的 Spec。

比如，客户说所有销售人员都可以查看订单。那究竟是查看所有客户的订单，还是只能查看自己负责的客户？有没有权限修改订单？

这些细节都需要明确下来。

**Spec 的价值，是让不同 Agent 对同一个需求形成一致的理解，减少不同环节之间的理解偏差。**

当然，只有一份 Spec 还不够。

**这么多 Agent，谁先执行，谁后执行，任务怎么拆解，前一个 Agent 的工作完成以后，怎么检查质量，再交给下一个 Agent？**

这些都需要一套系统来组织。

**所以，CodeWave 在底层还搭建了一套 Harness，负责管理整个 Agent 团队的工作流程。**

比如，每个阶段都有对应的任务和质量检查。检查没有通过，就需要继续修改，不能直接进入下一阶段。遇到需要人来判断的地方，也可以要求人工确认。

而且，整套系统运行在企业的集群环境中，不再依赖某个程序员的个人电脑。每个 Agent 做了什么，修改了哪些代码，执行过程中遇到了什么问题，都可以记录和追踪。

这些记录也会成为企业自己的资产。比如开发过程中产生的 Spec、产品原型、架构文档、测试报告和原生代码，都会保存下来。

**这样以后客户提出新的需求，或者需要修改已有系统，就可以继续使用之前积累的资料，不需要每次都从头理解整个项目。**

而且，最终生成的是原生代码，企业可以直接审查和接管。

******#05******

**写在最后**

**听完网易的分享，又体验了他们的产品之后，我突然觉得，这其实就是一个 AI 软件工厂，也很可能代表了下一代 AI Coding 的发展方向。**

过去，一个完整的研发团队，就像我们公司，有产品经理、程序员、测试人员等等。大家相互配合，开发出一个产品，再推向市场。

但现在，CodeWave 尝试把整个软件开发过程变成一条由 Agent 驱动的流水线。

过去需要不同岗位协作完成的工作，开始由 Agent 连续执行，人则更多地负责需求判断、过程把关和最终验收。

我觉得，这很可能是接下来越来越多软件公司都会尝试的方向。

**但这件事也有很大的挑战，因为它会直接涉及企业内部的人员分工和工作流程。**

网易就提出了一个很有意思的设想。

过去，一个产品经理可能需要配十个开发人员。 **但随着 Agent 承担越来越多的开发工作，未来一个十人团队，可能会变成五个产品经理配五个开发人员。**

当然，这只是一个假设，但背后的变化确实值得琢磨。

这意味着软件公司的招聘结构、岗位职责，甚至整个团队的组织方式，都可能发生很大的变化。

其实过去一年讨论 AI Coding 的时候，大家已经意识到，程序员的工作会被 AI 改变。

**但之前我们更多关注的是个人效率，一个程序员借助 AI，究竟能完成过去多少个人的工作。**

现在，这个问题开始延伸到整个企业了。

**如果 AI 已经能够承担软件开发流程中的大量工作，那么软件公司是不是也应该重新考虑，究竟需要什么样的人，以及应该怎么组织这些人和 Agent 一起工作？**

我觉得，这可能是接下来比单纯讨论 AI Coding 提效多少，更值得软件公司认真思考的问题。

因为个人使用 AI 的生产率提升，不会自动转化为公司的产出提升。
