# 半年月活涨20倍，ARR破4千万的OpenCode，如何从“完了”到“火了”？

**作者**: 随机小助手

**来源**: https://mp.weixin.qq.com/s/AGDh4YxFUqyKVMLk9Zpd4g

---

## 摘要

OpenCode作为不绑定单一模型的开源Coding Agent，半年内月活从65万暴增至1300万，ARR突破4000万美元。其爆发首先得益于Anthropic限制Claude Code订阅接入带来的反向营销效应，让产品意外出圈。但用户持续留存的根本在于开源模型能力提升与降价降低了使用门槛，以及团队将“选择权”真正做成了产品，通过建立底层模型数据库消除信息差，使用户能便捷地接入和切换多种模型，成。

Linkloud 引言

OpenCode 是一个可以接入任意模型的开源 Coding Agent，常被拿来和 Claude Code 做对照。Claude Code 由 Anthropic 推出，OpenCode 则希望成为不属于任何一家模型公司的开放入口。过去半年，它的 **月活从年初约 65 万增长到 6 月底约 1,300 万，接近 20 倍** 。

这轮增长踩中了几件同时发生的事：Anthropic 曾限制用户把 Claude Code 订阅带到 **OpenCode** 中使用，意外让更多人注意到这款产品。开源模型的能力逐渐接近前沿模型，开始能够承担真实工作；更低的价格也让那些难以负担每月 200 美元订阅费的用户进入市场。东西半球用户错峰使用，进一步提高了 OpenCode 的 GPU 利用率，也改善了它的单位经济性。

本文整理自 **YC** 对 **OpenCode 联合创始人兼 CEO Jay V** 的访谈，看看这款不押注单一模型的产品，如何把选择做成增长。Enjoy！

## 01\. 一次限制，让 OpenCode 被看见

今年年初，OpenCode 的月活只有约 65 万。一月第一周，团队开始注意到，Anthropic 开始限制用户在 OpenCode 中使用 Claude Code 订阅。

限制方式很直接，只要请求的 System prompt 里出现 “OpenCode” 这个词，请求就会被拒绝。

Anthropic 会这么做，并不难理解，它在补贴使用成本，自然希望这些补贴留在自己的产品里。但对不少用户来说，这个限制并不受欢迎。

不过这带来了一个意外结果， **那些原本不知道 OpenCode 的人开始注意到它** ：Claude Code 为什么要专门限制这个工具？还要特意拦住它，那它大概值得看一眼。

> “它把 OpenCode 和 Claude Code 放到了同一个 Pedestal 上。”

因此，原本它只是众多 Coding agent 中的一个，这次限制之后，第一次被单独挑出来比较。

类似的事也发生在 Instacart 身上。之前亚马逊收购 Whole Foods 时，“Instacart 要完了”一度成了个梗。结果，越来越多美国杂货商开始研究 Instacart，反而带来了一波签约。 **“被宣告要完”，有时反而会让更多人注意到你** 。

到 6 月底， **OpenCode 的月活已经增长到约 1,300 万，周活约 460 万，ARR 约 4,000 万美元** 。

同一时期，限制和支持同时出现。Codex 的一位主创工程师曾发文提到，约 5% 的 Codex 订阅用户会用 OpenCode 作为主要 Harness，调用底层 API。随后，Codex 官方正式支持了这种用法。

一边是限制，一边是开放，这说明不同模型公司对 OpenCode 的判断并不一样。

但无论是限制还是支持，带来的都只是一个入口，它们解释不了增长为什么能持续。真正的问题是，用户进来之后，为什么没有立刻离开。

## 02\. “选择”需要做成产品

![](https://mmbiz.qpic.cn/sz_mmbiz_png/bibgT3aJCdkY7qRnQjGAaSEgg0w0sISzkiaibnsUxeiaEbgM9hb6OxiaktuWASTwhfQVN8mwNoibXX4sqfnLB0Sw9gbaYtcBSGaDjPNeNXXWSibQ4A/640?wx_fmt=png&from=appmsg)

OpenCode 从一开始就没有打算做某个模型的附属工具。

它的名字指向的是另一种定位：当市场里已经有一两家强势玩家，其他参与者会需要一个开放的替代方案。OpenCode 想成为的，就是这个方案。

> “我们不是在模型公司里挑赢家，我们是在给整个领域下注。”

要让用户真正拥有选择，不能只把不同模型的 API 接进来。

OpenCode 上线时支持 70 多个模型和供应商。模型名称、版本、价格、上下文长度和接入方式都在不断变化，用户很难自己处理这些信息，团队为此单独做了 models.dev，从零建立模型和供应商数据库。

这个数据库把分散的信息整理成了可以直接使用的产品能力，用户不需要先研究每个供应商的接口，也不必因为想换一个模型，就重新搭一套工具。

OpenCode 的边界也不只停留在终端界面。

Ramp（美国一家金融科技公司）内部有个团队做了一个 Slack bot。这个 bot 的背后运行着 OpenCode 的 server 和 agent loop，而不是 OpenCode 的终端 UI。server 负责提供后台能力，agent loop 负责调用模型、执行任务，再根据结果继续推进下一步。

这两部分可以脱离 UI 单独使用。Ramp 把它们接进 Slack bot 后，OpenCode 的核心能力就进入了另一个工作流。

**模型能力和使用模型的界面，因此不必绑在一起** 。模型公司可以提供模型，OpenCode 则可以成为调用模型、组织任务和执行工作的工具层。

用户可以根据价格、速度和任务类型切换模型， **模型公司也会被放在一起比较，价格、能力和服务都会变成竞争的一部分** 。反过来，如果用户被锁在单一供应商里，就很难享受到这种竞争带来的好处。

不过，选择能否成为优势，最终还取决于：除了前沿模型之外，其他模型是否已经值得被选择。

## 03\. 模型够用，选择才有意义

OpenCode 早期吸引的，主要是想把 Claude 订阅带到 OpenCode 中使用的用户。

去年夏秋，GLM、Kimi、MiniMax 等开源模型陆续出现。开源和前沿模型之间的差距开始缩小。它们未必在所有任务上都更强，但已经可以完成不少真实工作。

今年 2 月，数据里出现了一个更明显的信号。连续 4 周，Kimi 的用量第一次超过 Sonnet 和 Opus 的总和。此前从未出现过这种情况。

这让团队开始相信，开源模型已经不只是便宜的替代品。它们足以承担真实工作，也值得围绕它们推出低价订阅计划，服务更多用户。

OpenCode 还公开了一个数据页 `opencode.ai/data` ，记录 OpenCode Go 订阅用户对不同模型的实际使用情况，不代表全球开发者的模型选择。

![](https://mmbiz.qpic.cn/mmbiz_png/bibgT3aJCdkbBDRY0BgDzUJlcUq40z43jiaRLTgmxicRWtIicH6VnwRflR0roBQ63yBbgbBiaDNrB17pqldworqcjYxlqpSDhadpLzGSibkgKHgRM/640?wx_fmt=png&from=appmsg)

GLM 出现后，DeepSeek 的份额一度下滑，后来又回升。从独立用户数看，DeepSeek Flash 约 3.8 万，DeepSeek Pro 约 3.1 万，GLM 5.2 接近 3 万。 **不同模型各有用户，没有一个模型能在所有场景里胜出** 。

差异大都来自很具体的使用习惯。

DeepSeek Flash 足够便宜，用户快用完额度时，会切过去继续工作；Kimi 的早期吸引力不只来自模型能力，也来自推理速度，使用体验接近实时；GLM 5.2 则因为前端设计表现，获得了一部分用户的偏好。

模型不会只按“强”或“弱”简单的线性排列， **价格、速度和特定任务上的表现，都会影响用户的选择** 。

不同模型仍在竞争，但竞争不再只是谁的能力更强，也包括谁更快、更便宜，或更适合某一类任务。原本被高价订阅挡在门外的用户，也开始进来了。

## 04\. 全球用户，也带来成本优势

![](https://mmbiz.qpic.cn/sz_mmbiz_png/bibgT3aJCdkZDpkqdcfyiaGTIBYcokCDRq4GuLsOEmrVatT8xCm0XQOzvaOUgW0hUhnDoFBtKkNMjQ8HpxFaRfYR3uFicnAWrMqOhGBwoiazGv4/640?wx_fmt=png&from=appmsg)

在 OpenCode Go 的用户中，中国占约 18%，印尼占约 5%，巴西占约 7%，越南等市场也很活跃。

因为在很多地区，每月 200 美元的 Claude Code 订阅其实并不现实。价格更低、模型选择更多的工具，让原本用不起这类产品的人也能开始使用 Coding Agent。

这些用户带来的不只是增长，还改变了 OpenCode 的成本结构。

东西半球的用户交错使用产品。东半球进入工作时间时，西半球正在休息。西半球开始工作后，东半球又逐渐离开高峰。 **一天之内，OpenCode 的 GPU 使用没有明显的高峰和低谷，而是保持在相对稳定的水平** 。

稳定的利用率意味着同样的 GPU 资源可以服务更多请求，运行模型的单位成本也会更低。对于主要服务单一地区市场的产品，这种跨时区的需求分布并不容易获得。

另一边，大型企业选择 OpenCode，往往不是因为价格。

十多家大型 Fortune 500 公司已经在使用 OpenCode。它们看重的是模型选择权，不希望把开发流程锁在单一模型或单一 Harness 上。很多时候， **企业并不是先被销售说服，而是员工已经在内部用起来了，采购和安全流程才随后跟上** 。

> “真正的 PMF，是企业主动来找你签安全协议，好让他们能用上产品。”

企业提出的需求，其实是层层递进的。

最开始是开发团队已经在用 OpenCode，企业随后想弄清楚，除了开发者，这套能力还能放到哪里。非技术岗位能不能用？公司自己的产品，能不能把 Coding Agent 放进核心流程？

当使用范围开始扩大， **问题就从“能不能用”变成“怎么管”。**

不同团队未必都需要前沿模型，有些团队更在意能力，有些团队更在意成本。企业因此会问，能不能限制部分团队使用的模型，或者按团队设置不同的 Token 预算和使用规则。

再之后，是可见性的问题。

有企业希望知道，员工究竟在用 Coding Agent 做什么。这已经不只是后台加一个管理功能，而是在考虑 OpenCode 要不要进入企业内部的管理和监控体系。

产品从个人工具走进企业，往往都会经历这条路径： **先解决一小群人的问题，再进入更多工作环节，最后碰到成本、权限和边界** 。

## 05\. Token 成了新的获客成本

过去，很多产品花广告费获取用户，而 AI 产品要先花 Token，让用户真正感受到它能完成工作。

Coding Agent 的体验门槛不低，用户需要用它做完几次真实任务，才会理解它能带来什么变化。这个过程需要消耗大量 Token，前沿模型公司通常会补贴这部分成本，帮助用户跨过最开始的门槛。

> “过去的 CAC 很多建立在广告上。现在，这个等式变了，它建立在用 Token 获取用户上。”

OpenCode 也在补贴。

免费层的作用，是让更多人先体验到 Coding Agent 的价值。开源模型的价格和能力逐渐达到可用水平后，订阅计划才让用户把尝试变成日常工作。一部分深度用户会继续在公司内部推动使用，最后进入企业采购和安全流程。

这条路径并不轻松，免费层和被补贴的使用都是成本。

而收入主要来自两部分： **一部分用户按 Token 付费** ，OpenCode 因为调用规模大，可以拿到更低的价格，差额构成利润空间； **另一部分是订阅收入** ，随着重度用户增加，前期的补贴成本才有机会被覆盖。

规模也让 OpenCode 成为多数开源模型的重要客户。它需要这些模型持续进步，模型公司也需要更多真实使用场景。用户在不同模型之间切换，模型公司会在价格、速度和能力上持续竞争，最终受益的是使用者。

这两条收入线已经形成了相当规模，但口径需要分开看。

**按 6 月的数据，推理业务约为 3,100 万至 3,300 万美元。按最近一周的数据推算，这部分收入约为 3,800 万至 4,000 万美元。订阅业务则有约 16 万月付用户，对应约 1,800 万美元 ARR。**

这些数字说明，OpenCode 已经把免费体验、订阅和按 Token 付费这套路径跑了起来。但推理收入和订阅收入属于不同业务线，不能在没有解释口径的情况下简单相加，更不能直接当成已经实现的利润。

## 06\. 多年积累，赶上窗口

OpenCode 的增长来得很快，但团队并不是在机会出现后才起步。Jay 从 2006、2007 年开始创业，2016 年到 2021 年间，他申请 YC 九次，参加过四次面试，最终进入 2021 年冬季批次。终端 UI、开源产品、云服务，以及服务不同类型用户的经历，都在这段时间里慢慢积累下来。

做 OpenCode 前，团队刚把上一个产品做到收支平衡，Claude Code 出现了。Jay 和另一位联合创始人 Frank 一直是 NeoVim 的重度用户，Cursor 的交互方式并不太吸引他们。Claude Code 则让他们第一次感觉到，AI 不只是自动补全代码，它已经能真正接手一部分工作。

不过，当时的终端体验仍不够成熟，因此他们定下了一个很具体的方向： **OpenCode 打开后的第一感受，要像一款现代终端应用** 。

他们还曾做过一个通过 SSH 下单的咖啡订阅服务，用户登录终端购买咖啡，第一年卖出约 10 万美元。这个项目看上去有些另类，却让他们持续摸索一件事：终端除了写代码，还能承载怎样的产品体验。

团队也很早养成了 Build in public 的习惯。既然代码本来就是开源的，那么产品进展、增长数据和关键决策也没有必要藏着，这样长期下来，社区就能持续看到产品如何变化，有人甚至把这个过程形容成一档真人秀。

模型在变，价格也在变。OpenCode 能在这个窗口里迅速起量，靠的不只是赶上了 Coding Agent 的热潮，也靠团队过去多年积累的产品判断和工程能力。
