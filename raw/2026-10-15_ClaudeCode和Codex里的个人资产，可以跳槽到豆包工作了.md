## 摘要

豆包工作于10月14日升级，支持从ChatGPT、Claude Code、TRAE Work等产品一键导入历史对话、记忆、技能、连接器等AI资产，并可在已有上下文基础上继续推进任务，同时新增自动同步、消息注释、对话摘要侧栏等功能，让用户能更自由地切换AI产品而无需从零开始。

今年，Coding Agent、办公 Agent 的产品体验，成了各个厂商的关注重点。

大家都在想办法，在模型之外，如何让自己家的 Agent 更好用。为此推出了很多操作，像是 **让用户能够直接用其他 AI 产品里积累的数据和工作记录。**

毕竟每家 Agent 「风味」都不一样，谁家生态好就用谁家才是 C 端用户常态。

**10 月 14 日，豆包工作也迎来了一次类似的功能升级。** 现在支持从 ChatGPT、Claude Code、TRAE Work 等产品一键导入 AI 资产。

用户过去积累的历史对话、任务偏好、技能、连接器、记忆和项目等内容，都支持迁移。而且，导入之后，用户可以直接打开过去的对话，在已有上下文的基础上继续推进任务。

除此之外，豆包工作还增加了一些其他产品体验上的升级。比如「在新对话中继续」、消息注释、对话摘要侧栏等等。

🚥

「十字路口」团队在第一时间进行了实测。

不过在分享实际体验之前，想先聊聊我们对于「用户的 AI 资产」的一些思考，以及为什么你和 AI 的聊天记录，正在变得越来越有价值。

你和 AI 的聊天记录，正在变得越来越有价值

过去使用 ChatGPT 这样的 AI 产品，我们可能没有特别在意自己积累了多少数据。因为，我们最主要的交互其实就是「对话 → 获得文字答案」，然后整个交互基本就结束了。

所以在那个时候，导出 ChatGPT 聊天数据，这件事情其实并没有太大的意义。

但现在情况不太一样。

尤其是在 Coding Agent、办公 Agent 出现之后，越来越多的用户会围绕某个长期任务，持续跟 AI 进行对话。

**这些信息，其实已经成为我们个人工作流程的一部分，进而在某种程度上，成为了我们的「个人 AI 资产」。**

如果细分用户积累的 AI 资产的话，大致可以划定为几个部分：

【1】 **历史对话与项目**

用户过去讨论过什么、做过什么任务、已经推进到了哪一步。

【2】 **个人记忆与工作偏好**

比如习惯使用什么语言、喜欢什么表达方式、有哪些长期要求。

【3】 **技能与连接器**

用户自己配置过的 Skills、外部工具和工作流程，让 Agent 能够按照熟悉的方式完成任务。

【4】 **工作产物**

比如已经生成的文档、代码、研究资料和其他成果。

所以，AI 资产迁移有一个非常直接的价值，就是 **用户可以更自由地选择 AI 产品，而不用每次换工具，都重新开始。**

这也是豆包工作这次更新值得关注的原因，它让来自不同 AI 产品的部分工作积累，可以继续在新的 Agent 里发挥作用。对于普通用户来说，则不需要理解太复杂的技术原理。

下面，我就拿 Claude Code 和 Codex 里的两个实际案例，看看之前做过的工作，如何在豆包工作里接着做，甚至做得更好。

Claude Code + Codex ➡️ 豆包工作

现在，在豆包工作左下角打开「设置」，点击「 **数据导入与同步** 」，就可以自动扫描电脑中使用过的 Coding Agent，包括 TRAE Work、Claude Code、ChatGPT（Codex）等。

可迁移的数据也很丰富，包括历史对话记录、记忆、规则，以及 CLAUDE.md、AGENTS.md、MEMORY.md 等文件，还有此前配置的各种 Skills。

如果没有特别的顾虑，也可以直接勾选全部数据，一次性完成导入。

完成首次导入后，还可以直接开启「自动同步」。开启之后，系统每天都会自动导入同步范围内的最新数据，不需要再手动添加。

我个人平时用得比较多的是 Claude Code 和 Codex。

比如最近这几天，我们一直在策划 **今年 12 月 31 日在新加坡举办的一场年末 Vibe Coding 活动，名字叫作「Last Commit Before Midnight」** 。

目前，这场活动还处于比较早期的策划阶段，但我们已经在 Claude Code 和 Codex 里积累了一些策划思路、研究资料和视觉设计素材。

所以，正好可以拿这个真实项目来做一次测试，看看 **豆包工作这次的 AI 资产迁移功能，究竟能把多少已有的工作成果带过来，以及迁移之后能不能直接接着做** 。

**「Last Commit Before Midnight」**

首先，在 Claude Code 里，我其实已经做了不少前期准备，包括活动名称的设计、活动方案的初稿、相关提示词的打磨，甚至还调研了一些适合这场活动的 Vibe Coding 视觉风格。

这些内容都可以通过豆包工作的数据迁移功能，直接导入到豆包工作里。

而且，迁移过来的内容在展示上也做了适配。比如 Claude Code 里常用的提示词块、Callout 等内容，在豆包工作里都有对应的图形界面，查看起来也比较直观。

我之前已经在 Claude Code 里完成了 **活动方案 V0 的完整框架提示词** 。

导入数据后，就可以直接在豆包工作的同一个对话 Session 里继续，让它根据提示词生成一份完整的活动方案。

这份方案可以包含开头摘要、确认清单、决策事项、来源清单，以及流程时间轴、宣传节奏、预算条形图和 HTML 模块等可视化内容。

毕竟团队内部更习惯用飞书协作，所以最终可以整理成一份方便继续编辑的云文档。

这份活动方案 V0 已经相当完整了。

豆包工作结合我们提前准备的资料，又进一步调研了场地、票价、预算，以及新加坡跨年烟花、交通管制、Luma 费率、SFA 许可等信息。

追问

之前还在构思阶段时，我也在 Claude Code 里简单调研过一些 Vibe Coding 的视觉设计方向，比如比较经典的黑白 ASCII 编辑风。

这些内容导入豆包工作后，就可以直接选中对应的段落，点击「追问」，继续深入探索这个设计方向。

这样就可以直接基于这段上下文继续推进。

比如，我会 **让豆包工作逐一打开调研中的案例网站，分析其中值得借鉴的设计方向，并为每种风格搭配参考图** 。

参考图优先使用案例网站的实际截图，只有无法访问时才考虑 AI 生成。最后再把案例、设计者、借鉴点、链接等信息整理成飞书多维表格，方便后续作为设计参考资产。

这样一来，这场活动的初步视觉风格参考资产就整理好了，后续设计也有了可以直接借鉴的素材。

为什么要提前整理这些视觉风格资产？

因为我平时更喜欢用 Codex 做图形和视觉设计。GPT-6 Astra 加上内置的图像模型，整体用起来比较顺手。

此前，我已经在 Codex 里开了大量 Session，做过这场活动的资料调研、Vibe Coding 项目收集，甚至生成了一整套活动视觉物料。

但我还想尝试更多不同的设计风格。

所以，这次 **先让豆包工作整理出一套视觉风格参考资产，再把 Codex 里的历史项目导入进来，在已有设计的基础上，继续探索几个新的视觉方向** 。

面向东亚 Vibe Coding 的案例设计

一开始做调研时，我们就确定了一个重要方向，希望这场活动能更多地面向东亚和东南亚。

因为我最近发现，日本、韩国以及东南亚有很多非常有意思的 Vibe Coding 项目。但大家的注意力往往集中在美国，其实亚洲也有不少值得关注的作品，而且很多项目都融入了当地文化。

所以，我一开始就让 Codex 搜集了几十个亚洲有趣的 Vibe Coding 项目，并整理成了一份完整的亚洲 Vibe Coding 案例库。

这些内容都可以直接导入豆包工作。导入后，豆包工作可以直接打开和查看对应的 MD、CSV 文档，甚至 CSV 表格的排版效果，比 Codex 里还要好一些。

这样，就可以在豆包工作里一键将整个亚洲 Vibe Coding 案例库转换成一份可视化的多维表格，方便后续查看和筛选。

不过，单纯把 CSV 转成多维表格，展示效果还是比较简单。我更希望能 **直接看到这些 Vibe Coding 项目的实际效果** 。

比如，日本 AI 博主 Yasuna 就做过一个很有意思的日语相关项目，融入了不少当地文化元素，很值得拿出来展示。

所以，我先让豆包工作挑出三个案例，一步步尝试用纯代码制作动画视频。

具体来说，就是用 **Python + NumPy + Pillow** 逐帧绘制，再通过 **ffmpeg** 编码成 MP4。

比如新加坡地铁客流可视化、青空文库虚拟主播，还有基于 100 字角色设定的 AI 对战等。

从实际效果来看，豆包工作在这种纯代码动画视频的制作上，表现还是挺不错的。

在新对话中继续

现在，豆包工作还支持一个新功能，叫作「 **在新对话中继续** 」，这个功能在图像视觉设计中非常好用。

比如，我之前已经在 Codex 里为整场活动制作了一套比较完整的初版视觉物料。

这些内容导入豆包工作后，都可以正常显示。而且在右侧的「对话摘要」里，还能直接看到之前生成的图像资产和对话内容，方便随时查看和继续修改。

然后，在豆包工作左侧的项目栏中，直接选中对应的 Session，点击「在新对话中继续」，就可以基于之前的内容开启新的对话。

相当于在同一个项目下新开一个 Session，继承原 Session 的 Memory 和上下文，同时保留原来的对话，不会影响之前的工作。

所以，把 Codex 里负责视觉设计的 Session 迁移到豆包工作后，我就可以直接让它整理并列出目前这版活动的全部视觉物料设计：

现在通过「在新对话中继续」，就可以直接 **继承初版活动视觉物料的上下文，在此基础上重新设计一套不同风格的版本** ，比如更偏黑白像素、复古风格的活动物料：

这样使用「在新对话中继续」，效率确实会提升很多。

到现在，我们已经积累了不少活动资产，包括收录 38 个项目的东亚 Vibe Coding 案例库、案例与活动环节的对应表、成果数据、包含 17 项已完成物料的视觉设计清单，以及整份活动方案 V0。

接下来，就可以 **把这些多维表格、文档和图像资产全部交给豆包工作，让它统一整合进最初的活动方案 V0** 。

这样，一份相对完整、可以继续推进的活动策划方案就有了。

不得不说，整套工作流跑下来，效率确实比之前更高了。

以前，我会单独在 Claude Code 里做提示词设计、视觉风格调研，再到 Codex 里做图像物料设计和 Deep Research。这些工作虽然都能完成，但成果分散在不同的工具里。

现在， **豆包工作相当于成了整套工作流的「终点站」。**

它可以把不同工具里的对话、资料和成果直接迁移过来，沿着之前的工作继续推进，最后再转换成飞书文档、多维表格等适合团队协作的内容。

这样就 **省去了反复导出、分享 CSV、HTML、Word 等文件的步骤，团队也可以直接在飞书里继续协作** 。

**有些时候，一项看起来很简单的交互优化，给用户带来的体验提升，其实是非常大的。**

其实，OpenAI CEO Sam Altman 在一场 TED2025 访谈中，就已经谈过类似的观点。

他当时提到，OpenAI 除了模型迭代之外，还需要做另一件事情。

**「我们必须打造一款优秀的产品，而不只是一款优秀的模型。」**

这个判断，放到今天的 Agent 市场里依然非常合适。

现在，我们开始看到 Codex、Claude Code、豆包工作这样的产品，主动支持接收其他 Agent 的工作记录。

这也意味着，用户不必因为已经在某个产品里积累了大量数据，就一直被限制在同一个产品中。

🚥

**未来的 AI Agent，既要有能力帮用户完成新的工作，也要能够理解用户过去已经做过的工作。**

而让用户的工作积累能够持续使用，甚至在不同 Agent 之间自由流动，可能会成为接下来 AI 产品体验竞争中很值得关注的一部分。
